# 玛丽（MARIE）· 总览
---

## 一、这套架构是做什么的

玛丽是一套**用通用、可复用、尽可能灵活的原子化实体，低成本、快速构建不同场景下复杂系统的架构**。

它要解决的问题是：**给定一类场景，怎么用同一套积木快速搭出一个系统，这个系统接收可量化的目标，把目标拆解到可观测的指标上，持续选择方法、生成预测、执行方法、观测结果、忠实记账、报告误差，不断满足目标、或尽可能向目标靠拢。**

玛丽执行给定的逻辑、记账、对账、报告，把判断留给该做判断的人。具体来说：
 - 玛丽对于已知的问题，可以自己决策，比如知道如何拆解目标、应该选择什么方法、方法的执行结果成功或发生已知的异常时，玛丽可以按照既定的方式运作；
 - 对于未知的问题，比如不知道该用什么方法拆解目标，拆解出的指标上产生冲突不知道如何处理，或是选择的方法存在资源冲突且无法确定优先级等情况下，原则上玛丽选择上报；

### 1.1 为什么值得存在

目标——系统要服务的东西——是无穷的、事先未知的、随时在变的；需要随时间积累的资产（知识、方法、执行记录）是有限的、必须沉淀的。把两者绑在一起，目标一变系统就要重构或报废。

玛丽的答案是把它们分开：

> **用一池子持续沉淀、相对稳定的单元，服务无穷且不可预知的目标组合。**

系统的能力落在**组装的能力**与**池子的厚度**上。

## 二、适用范围

### 2.1 三个条件

| # | 条件 | 含义 |
| --- | --- | --- |
| C1 | **目标可量化** | 目标能表达为指标上的取值，可以是单值，也可以是向量加红线 |
| C2 | **环境有可量化指标** | 目标本身是这些指标的一部分，或能拆解到这些指标上 |
| C3 | **持续运营** | 系统长期运行，使环境不断满足目标、或尽可能向目标靠拢 |

三条之外不额外设限。**目标可达和不可达都在范围内**：可达成是特例，不可达成是常态。

### 2.2 什么样的环境是“可量化”的？

人类和机器观测现实世界，得到的是其中一部分指标，而非世界的全貌，比如人眼观测到的不是所有的颜色，而数字信号从来都是模拟信号的抽样；用文字记录现实世界，是用符号化的文字对这些指标的又一次精简提炼，比如颜色、时间、形状等等。所以：

- **不存在"无法量化的场景"**——现实世界输入任何现代图灵机系统，必然是已成指标的东西，必然是存在信息量损失的。
- **任何场景的输入都是有信息量损失的**——影响结果的既有观测的准确度，也有指标的完备程度，这二者一定是不完美的，自然语言形式的输入更是如此。

### 2.3 持续运营的含义

持续运营的机制来自**预测加工模型**：系统是分层的，且每一层反复运行同一个循环——**预测 → 观测 → 误差 → 修正**。误差在哪一层被处理掉，取决于那一层有没有手段；没有手段才向上报告。

在复杂系统里，比如企业、组织的运营，目标往往永远不会真正"完成"，只要系统还在运转，问题总会不断出现。玛丽架构的目的是**持续解决这些问题、不断向目标靠拢**。

而对于简单的一次性任务，虽然并不一定有优势，这套机制也是能够生效的。

由此有三条后果，它们贯穿整套设计：

1. 收敛判据取**误差随时间的曲线**是否被压在容差带内并保持稳定，不取"某天是否达标"；
2. 目标进入容差带之后系统不停机，转入**正常运转**：继续观测记账，但不主动推送，突破即唤醒；
3. **报告分层**：入账留全部事实，报告让人知道有什么变化，上报只请人做只有人能做的动作。把它当成"少打扰人"的技巧就误解了它的位置——它是"系统什么时候才该找人"的判据（见 05 §三）。

## 三、架构本体的三件东西

### 3.1 玛丽（MARIE）：原子化实体

单个玛丽 = 负责一个输出指标的组件。她做三件事：往下传子目标、往上传观测与误差、在本地执行拆解逻辑并选择方法。

| 字母 | 回答的问题 | 含义 |
| --- | --- | --- |
| **M**otivated | 为什么存在、如何生长 | 运行时被目标激发才存在，没被激活不消耗资源；构建时被目标盘点而复用，灵活应对不同目标；没有已有玛丽、且知识匹配不上的就是缺口，需要上报 |
| **A**uthorizable | 为谁服务、看到哪个世界 | 授权加在**数据内容**上，而非组件，且只有一个作用面——方法、历史、数据都在同一套存储里。同一个玛丽为不同对象服务时，职责不变，能看到的数据不同，因此能用的方法与据以判断的历史也不同 |
| **R**epository-based | 状态在哪里 | 玛丽不持有长期状态，她的输入输出指标恒定，其余一切都在存储里，存储决定了玛丽能选择的指标、拆解方法、可选行为 |
| **I**nference | 干什么活 | 局部推理：执行拆解逻辑、选择方法、记账对账 |
| **E**ntity | 怎么被组装 | 可引用、可组合 |

两条关键设计约束：

- **玛丽以"指标"而非"任务"定义。** 任务是易变的，对指标的拆解和方法执行是稳定的，用稳定的玛丽们服务易变的任务是复用能够成立的原因；
- **玛丽要小、职责单一。** 颗粒度越大，复用率越低。颗粒度是否合适，用复用率实测校准。

### 3.2 存储：原文层 + 知识层

存储由两部分构成：

| 层 | 内容 |
| --- | --- |
| **原文层** | 切片、规范化、去掉无意义符号后的自然语言原文 |
| **知识层** | 由原文提炼出关键概念、以及概念之间的关系所形成的知识图谱，其中概念作为节点有类型，关系作为边有固定的类别 |

**概念类型（节点类型）：**
- 单独概念：逻辑学上的单独概念，用于表示一个特定的实体。在游戏日志中，角色名、技能名、物品名、特定状态等均为单独概念。
- 普遍概念：一类事物或属性的概括性概念。
- 时间概念：时间点或时间段。
- 位置概念：地点或场所。
- 事实概念：描述一个发生过的事件、状态或关系。事实是图谱的枢纽节点，多个概念通过"参与"关系关联到同一事实。

**关系类型（边类型）：**
- 实例：单独概念A是普遍概念B的实例
- 是：概念A和概念B是等价的
- 属于：概念A是概念B的一个分类
- 参与：概念A是事实B的参与者之一，这里A可以是事实B语句中的主语、谓语、宾语、定语、状语、补语等等，任意一部分均可，只有时间和地点除外（用"发生"关联）
- 发生：事实A发生在时间或地点B
- 导致：事实A导致了事实B
- 先于：事实A先于事实B发生，但不构成或不确定是否构成因果关系

两点纪律：

1. **不重新发明、不质疑其形态。** 这套存储同时服务其他 RAG 业务，它就是这么设计的；
2. **玛丽不直连存储。** 二者之间隔一层查询接口；

### 3.3 逼近循环：系统的动力

见 §2.3。预测加工循环是每个玛丽在每个主循环上反复运行的东西，也是"持续运营"这个条件在系统内部的实现形态。

## 四、组装：树、森林、图

| 形态 | 含义 |
| --- | --- |
| **玛丽树** | 单一目标拆解出的树 |
| **玛丽森林** | 多个目标并行，各自的树共享同一批原子实体 |
| **玛丽图** | 更复杂的结构：共享节点、环、跨目标依赖 |

三种形态由同一批原子实体装出，**不需要新的内核概念、也不需要新的字段**——形态差异全部落在事件的负载里。

树、森林、图都是**单次运行**的产物，一次运行结束后解散；持续运营表现为**不断生成新的树和图**，去维护或逼近目标。这是因为，玛丽是知识与经验的产物。一次运行结束后，知识和经验可能已经变了，玛丽也好、整棵树/森林/图也好，都可能需要更新。所以每次从最新知识重新组装，不去修补旧图。
更具体地说：
- 运行中的图是静态的，不存在"运行中改图"的一致性问题；
- 知识更新在下一次组装时自然生效，不需要任何图迁移机制；

**三条推论**：

1. **未比对预测的版本语义不变**：预测按生成时绑定的逻辑版本比对，因此历史账目永远可回放。"下次组装用最新知识"与"已生成的预测用旧知识"是两条并行规则，不冲突；
2. **一次运行的终点 = 所有预测已比对**。预测跨运行到期就没有人对它负责对账，所以运行不能提前结束；全部比对完之后，没有任何未了结的事，图可以散；
3. **运行时长因此由预测的观察期决定**，不由节拍数决定。一个观察期是四周的方法，会把这次运行拉长到四周。

## 六、内核与场景绑定

| 层 | 内容 | 谁负责 |
| --- | --- | --- |
| **内核** | 与场景无关的四件事：自上而下拆解、自下而上观测、选择并执行方法、统一格式记账 | 架构提供，不含任何业务词汇 |
| **逻辑源** | 一个插槽："拆解逻辑和方法知识从哪来" | 场景提供 |
| **场景绑定** | 逻辑源的具体形态 + 责任契约（谁来更新知识、要不要人确认） | 场景提供 |

**一条铁律**：玛丽执行期间永不修改自己的逻辑源。逻辑源的演化发生在内核之外。

**一条推论**：换场景时，改动只应发生在配置与知识里。**内核代码零改动**是可用机器判定的硬指标，不是一句设计意图。

## 七、设计原则（写代码和写文档时都守这几条）

1. **量化优先**：任何目标、方法效果、观测都必须落到指标上。说不清指标，就是还没想清楚，报缺口，不猜；
2. **玛丽是执行者**：她的动作就是"选择一个方法并执行"。这个方法具体是"自己去操作"还是"向人提一条建议"，由方法定义（执行体）决定，属于知识，不属于架构。企业场景里她通常提出建议，是因为那里的方法被定义为建议——不是架构在拦她；
3. **不合并异质信息**：来源性质不同的信息绝不混为一谈（自称的效果、推演的结果、实测的结果），否则对账体系会被污染；
4. **不做因果推断**：系统只声称误差与相关性，不声称因果。归因是事后从完整时间线上分析的事；
5. **缺口显式**：做不到的地方显式上报并**指出位置**，不许静默跳过、不许用看似合理的值填充；
6. **原子且单一职责**：组件小、词汇稳、接口薄。颗粒度用复用率校准；
7. **场景无关的东西才进内核**：内核里出现任何业务词汇，都是分离性失效的信号；
8. **措辞即设计**：文档里不用含糊的比喻代替机制说明。一个词如果说不清它在代码里对应什么，就换掉它。

## 十、术语

| 术语 | 含义 |
| --- | --- |
| 玛丽（MARIE） | 原子化组件：被激发、可授权、基于存储、推理、实体 |
| 内核 | 与场景无关的四件事：拆解、观测、选择并执行、记账 |
| 逻辑源 | "拆解逻辑和方法知识从哪来"的抽象插槽 |
| 场景绑定 | 逻辑源的具体形态 + 责任契约 |
| 原文层 / 知识层 | 存储的两部分：切片规范化自然语言原文 / 由原文提炼的概念与关系 |
| RQI | 玛丽与存储之间的薄查询接口 |
| 玛丽树 / 森林 / 图 | 单次运行组装出的三种形态；用完即散 |
| 指标 | 组件的锚点，也是系统与业务世界之间的稳定词汇表 |
| 目标 | 指标 + 目标值 + 容差带 + 期限 |
| 容差带 | 目标精度：误差达到多少才算目标未达成 |
| 预测 | 方法发起时生成的记录：方法与其版本、预期变化、观察期、状态 |
| 误差 | 观测与预测的预期之间的差。永远是投影计算，不落库 |
| 报告分层 | 入账（全部事实）/ 报告（有什么变化）/ 上报（请人做只有人能做的事） |
| 正常运转 | 指标都在容差带内：继续记账、继续进报告层，但不主动推送 |
| 缺口 | 系统做不到的地方，分类且带位置地上报 |
| 情态 | 信息来源标记：声明 / 推演 / 实测 |
