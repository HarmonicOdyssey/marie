# 附录 B · 术语表

> 术语按类别编排。**如果一个词在这里说不清它在代码里对应什么，就应该换掉它**（见 00 §七 设计原则第 8 条）。

---

## 一、架构

| 术语 | 含义 |
| --- | --- |
| **玛丽（MARIE）** | 原子化组件。M 被激发 / A 可授权 / R 基于存储（三个特性），I 推理（功能），E 实体 |
| **内核** | 与场景无关的四件事：自上而下拆解、自下而上观测、选择并执行方法、统一格式记账。不含任何业务词汇 |
| **逻辑源** | "拆解逻辑和方法知识从哪来"的抽象插槽。内核只按约定向它索取，不关心它内部是什么 |
| **场景绑定** | 逻辑源的具体形态 + 责任契约（谁更新知识、要不要人确认、无人场景中缺口由谁闭环） |
| **组件池** | 所有可实例化的玛丽定义的集合。**覆盖率 / 复用率是它的核心健康指标** |

---

## 二、实体

| 术语 | 含义 |
| --- | --- |
| **指标** | 玛丽的锚点，也是系统与业务世界之间的稳定词汇表。用稳定的词汇表服务易变的句子 |
| **组件颗粒度** | 一个玛丽负责多大范围。颗粒度用**实测复用率**校准，不用直觉 |
| **行为 = 组件 × 世界** | 同一份玛丽定义配上不同的世界视图，得到不同行为。回放、沙盘、冷启动、单元测试是同一件事的不同世界 |
| **角色模板** | 授权加在数据上时，玛丽成为可服务 N 个对象的模板，身上不留任何对象痕迹 |
| **授权的作用面** | 只有一个：存储里的数据内容。方法、历史、观测都在同一套存储里，所以不存在数据/方法/历史三层独立粒度——看得到什么就等于能用什么 |

---

## 三、组装形态

| 术语 | 含义 |
| --- | --- |
| **玛丽树** | 单一目标拆解出的树，单根无环 |
| **玛丽森林** | 多个目标并行，且各自的树**共享同一批原子实体**（只是多棵树各不相干的不算森林） |
| **玛丽图** | 存在共享节点、环或跨目标依赖的结构 |
| **环与时间延迟** | 循环依赖与自依赖统一处理为"读上一时间步、写下一时间步"，于是每个时间步内图无环 |
| **有状态指标** | 输出也是输入的指标（如"本期余额 = 上期余额 + 净流量"）。它没有专门的机制，就是环的一种 |
| **一次运行** | 从组装到解散的一个周期。终点是所有预测已比对（见 00 §五） |
| **用完即散** | 树/森林/图是单次运行的产物，运行结束即解散；下次从最新知识重新组装 |

## 四、知识与存储

| 术语 | 含义 |
| --- | --- |
| **原文层** | 切片、规范化、去掉无意义符号后的自然语言原文。是**依据** |
| **知识层** | 由原文提炼出关键概念及其关系形成的知识图谱。是**诠释**；两者冲突时以原文为准 |
| **RQI** | 玛丽与存储之间的薄查询接口。四类动作：取原文切片、取概念邻域、按指标取条目、取历史账目。**通用性的落点** |
| **拆解逻辑** | 指标 Y 怎么摊到它的输入指标上 |
| **方法定义** | 影响指标的可执行动作，含适用条件、多维效果预期、**执行体** |
| **执行体** | 方法定义里的一个字段（人 / 机器 / 外部接口）。它决定"执行"这个动作实际长什么样：提建议、自己操作、还是调外部系统。属于知识，不属于架构 |
| **多维效果** | 方法的效果是一组平等维度的指标变化，不区分主效果与副作用。预算不超支本身就是一个目标 |
| **预期变化** | 方法效果随时间展开的轨迹（第 1 周涨多少、之后爬到多少）。对账比的是轨迹，终值只是轨迹的末点；远期自带更宽容差带 |
| **编译态 / 解释态** | 拆解逻辑的两种执行形态：可形式化的编译一次后确定性执行 / 保留自然语言每次读取判断 |
| **熟成** | 解释态固化为编译态。是**需要确认的知识变更动作**，不自动发生 |
| **溯源指针** | 知识条目指向原文切片具体位置的指针。是"源变则派生失效"能够工作的前提 |

## 五、版本与情态

| 术语 | 含义 |
| --- | --- |
| **情态** | 信息来源性质：**声明 / 推演 / 实测**。强度顺序：实测 > 推演 > 声明。先验与实测绝不混淆 |
| **知识只追加** | 修改知识 = 追加新版本，旧版本永久保留 |
| **快照语义** | 未比对的预测按生成时绑定的版本对账，不追溯；新组装用最新版本 |
| **级联失效** | 源文变更后，所有派生自它的知识条目自动失效，需重新编制 |
| **共享世界 / 私有世界** | 通用知识共享、各对象的账目与私有方法隔离，按授权叠加成玛丽能看到的视图 |
| **晋升** | 私有世界中验证有效的方法经授权进入共享世界。组织学习的技术形态 |

## 六、运行

| 术语 | 含义 |
| --- | --- |
| **节拍** | 主循环推进的单位。频率可按指标分档 |
| **心跳巡视** | 独立于业务事件的定时检查，专门发现"什么都没发生、但本该发生"：预测到期未观测、数据源静默、会话超时 |
| **任务会话** | 每个（玛丽 × 本次运行）的工作记忆。**不是第二处真相**，可从存储中未比对的记录重建 |
| **预测** | 方法发起时生成的记录：方法与其版本、预期变化、观察期、状态。**未比对的预测**指尚未拿到观测的那些，由心跳盯办 |
| **预期变化** | 方法效果随时间展开的轨迹（第 1 周涨多少、之后爬到多少）。对账比的是轨迹，终值只是轨迹的末点；远期自带更宽容差带 |
| **观察期** | 一次预测要在多长时间窗内被观测检验 |
| **执行事件** | 方法执行过程本身的记录：已派发 / 已确认 / 已完成 / **前提未成立**。用于区分"方法不灵"与"压根没执行"；前提未成立时结果不可观测，这次预测无从验证 |
| **容差带** | 目标精度：误差达到多少才算目标未达成 |
| **正常运转** | 全部指标都在容差带内时的姿态：继续观测记账、继续进报告层，但不主动推送，突破即唤醒 |
| **报告分层** | 入账（全部事实）/ 报告（有什么变化，按级别推不推送）/ 上报（请人做只有人能做的动作） |
| **上报** | 请求一个只有人能做的动作：补知识、补方法、接数据、改规则、做取舍、担风险、发起尝试 |
| **报告级别** | 立即（系统停在这里等人）/ 尽快（有后续动作但会持续吃亏）/ 备查（只入账、只进列表） |
| **预测失准** | 某方法的历史实际效果系统性偏离预期且样本量够。触发条件是预测准不准，与单次误差是否出带无关；它要人做的是修订知识 |
| **降级阶梯** | 事先预编译好的降级序列（守全部目标 → 只守红线 → 保底），替代来不及做的实时仲裁 |
| **时间常数分层** | 同一个"预测 → 观测 → 误差 → 反应"循环在不同速度上运行：快层用预编译规则，中层用规则与模型，慢层是人 |

## 七、记录与投影

| 术语 | 含义 |
| --- | --- |
| **事件** | 不可变、只追加的记录单位。核心字段只含通用词汇，场景细节挂在负载里 |
| **快照** | 周期性锚点：某一时刻相关指标的全量值。频率是纯性能参数 |
| **投影** | 从事件现算出来的视图，不存储：误差、审计链、方法账目 |
| **误差不落库** | 记录层只存事实（观测值、生成预测时冻结的预期），误差永远是投影计算 |
| **因果父指针** | 每个事件指向"为什么发生"的那条事件。审计链靠它上溯到最初的目标 |
| **审计链** | 沿因果父指针向上遍历得到的链路，回答"当时为什么这么选" |
| **归因后置** | 记录时不替任何动作圈定结果；动作的真实效果是事后从完整序列分析得出的投影时计算 |
| **环境事件** | 世界中非由系统动作引发的事件（公休、竞对动作、政策变化）。与自身动作记在**同一条时间线**上，是事后分析能排除干扰的前提 |
| **幂等重放** | 重放事件流的过程必须只读。只有"追加事件"是允许的副作用 |

## 八、缺口与异常

| 术语 | 含义 |
| --- | --- |
| **缺口** | 系统做不到的地方。必须显式上报并**指出位置**，不许静默、不许猜 |
| **数据缺口** | 指标既不可观测也无法分解 |
| **知识缺口** | 拆解逻辑缺失，或只有无法执行的粗粒度描述 |
| **方法缺口** | 某环节没有任何可行方法 |
| **组件缺口** | 组装时发现某位置缺一个玛丽。缺口最精确的形态，直接指向池子该长什么 |
| **结构缺口** | 资源冲突无解，需要改变问题结构（加人、砍范围、改目标） |
| **仲裁即目标** | 资源冲突不打分排序，而是生成一个新目标交给同一套框架递归拆解 |
| **横向对账** | 指标之间的自洽性检查（"甲 +40% 而乙 −2%，至少有一本账有问题"）。只指出对不上，不判断谁假 |
| **命中率** | 推送出去的报告里，最终引发真实动作的比例。注意力过滤器的核心度量 |
| **报告噪声率** | 未引发任何动作的报告占全部报告的比例。反指标之一 |

## 九、自我治理

| 术语 | 含义 |
| --- | --- |
| **管道 / 玛丽是上下两层** | 执行本身永远是代码；玛丽化指的是它头上多一个管理者，常态零成本，异常时醒来 |
| **玛丽化判据** | 有可量化的目标 + 有可挑的方法 + 有异常要管。三条不满足就不该硬套 |
| **基岩** | 不可玛丽化的最小机制层：用最笨的方式报告自身故障（退出码、外部守护、独立告警通道）。规则：依赖集合与被监视对象不相交 |
| **系统自度量** | 系统对自己记账：覆盖率、可观测率、实测占比、样本量——回答"这份判断值多少信任"，也是冷启动何时结束的判据 |
