## 一、这一期的目标

M1 只回答一个问题：**这本账立不立得住。**

具体是三条：

1. **事实只追加**，写进去的东西不能再改，重放的过程只读；
2. **任何时刻的状态能重建**：最近快照 + 重放其后事件 = 当时的样子；
3. **任何一次决策能上溯**：从一次方法选择沿着因果父指针，能走回最初的目标。

误差、偏差统计、覆盖率这些**都是投影，现算，不落库**。M1 不判断业务对错，也不产生任何业务结论。

## 三、功能需求

### FR-1 事件写入

- 提供 `append(event)`，串行写入，返回事件 `id`；
- 系统内**不允许第二个写入路径**；
- 写入时校验：`type` 属于约定枚举；`caused_by` 若不为空则必须指向已存在的事件；`payload` 是合法 JSON；
- 校验失败则**拒绝写入并报错**，不许写入半条。

### FR-2 事件不可变

- 事件表上建立**只追加约束**：任何 UPDATE / DELETE 被数据库拒绝；
- 这条用 SQLite 的触发器实现即可，不靠约定；
- 需要更正时，追加一条新的更正事件（M1 只留出这个能力，不做更正流程）。

### FR-3 快照

- 提供"给当前时刻拍一张快照"的入口，内容是该时刻全部已知指标的当前值；
- 快照可手工触发或按配置的间隔自动触发（M1 手工触发即可，自动留到 M2）；
- 快照只增不改。

### FR-4 重放

- `replay(tick)`：从**不晚于该时刻的最近快照**开始，按 `id` 顺序重放其后事件，返回该时刻的完整状态；
- 没有快照时，从事件流起点重放；
- **重放全程只读**：不得写事件、不得写快照、不得触发任何对外副作用。

### FR-5 投影：误差

- 输入：一个预测（含生成时冻结的预期与观察期）；
- 算法：取观察期内该指标的观测，与冻结的预期逐点比对；
- **误差不落库**，只在查询时计算；
- 需要与目标容差区分：**对预测算误差**（观测 vs 预测的预期），**对目标看是否达成**（当前值 vs 目标值与容差带）。两者是不同的投影，不要合并。

### FR-6 投影：审计链

- 输入：任一事件的 `id`；
- 算法：沿 `caused_by` 上溯，直到没有父指针，返回按顺序排列的链路；
- 链路不完整（父指针悬空）时，**必须显式标记断裂**，不许静默返回半条链当成完整链。

### FR-7 投影：方法账目

- 按方法聚合：执行事件序列、观测序列、次数、平均效果、样本量；
- 全部现算，不落库；
- 样本量必须随结果一起返回——**没有样本量的平均效果是误导**。

### FR-8 RQI 与知识层

冻结四个方法，M1 只实现一个后端（YAML 文件 + Git）：

```typescript
interface RQI {
  slice(ref: SliceRef): TextSlice;                     // 取原文切片
  concepts(keys: ConceptKey[]): ConceptNeighborhood;    // 取概念邻域
  entries(indicator: IndicatorRef): KnowledgeEntry[];   // 按指标取条目
  ledger(query: LedgerQuery): LedgerView;               // 取历史账目
}
```

契约：

- **只读**：运行期间不许经 RQI 写任何东西；
- 每个返回的条目都要带 `key` 与 `version`；
- 事件的 `knowledge_ref` 字段只存 `key@version`，**不许把知识内容抄进事件**（见 08 §1.3）。

## 四、数据模型

```sql
CREATE TABLE events (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,  -- 序号即顺序
  tick          TEXT NOT NULL,      -- 业务时间
  recorded_at   TEXT NOT NULL,      -- 入账时间（与 tick 分离）
  world         TEXT NOT NULL DEFAULT 'main',
  type          TEXT NOT NULL,
  caused_by     INTEGER,            -- 因果父指针，可空
  snapshot_id   INTEGER,            -- 锚定快照，可空
  knowledge_ref TEXT,               -- {key}@{version}
  payload       TEXT NOT NULL       -- JSON
);

CREATE TABLE snapshots (
  id     INTEGER PRIMARY KEY AUTOINCREMENT,
  tick   TEXT NOT NULL,
  world  TEXT NOT NULL DEFAULT 'main',
  taken_at TEXT NOT NULL,
  payload TEXT NOT NULL             -- JSON：全部已知指标的当前值
);
```

事件类型（M1 全集，实现时按此枚举校验）：

| type | 含义 | payload 关键字段 |
| --- | --- | --- |
| `goal` | 目标下达 | 指标、目标值、容差带、期限、下达者 |
| `decompose` | 拆解 | 输出指标、各输入指标及其子目标 |
| `select` | 方法选择 | 候选集、各候选当时账目、实际选择、排序规则、知识版本 |
| `prediction` | 生成预测 | 方法及其版本、冻结的预期、观察期、状态 |
| `execution` | 执行事件 | 预测 id、状态（已派发 / 已确认 / 已完成 / 前提未成立） |
| `observation` | 观测 | 指标、值、情态、数据源 |
| `env_event` | 环境事件 | 事件种类与参数 |
| `report` | 报告 | 报告类型、关联事件 id 列表 |
| `knowledge_change` | 知识变更 | 条目 key、旧版本、新版本 |
| `heartbeat_overdue` | 心跳：预测到期未观测 | 预测 id |
| `heartbeat_silent` | 心跳：数据源静默 | 数据源、静默时长 |

两条约定：

- **`payload` 用自由 JSON**。除上表字段外，场景细节全部挂在 payload 里，**事件表永不因新场景加列**；
- `tick` 允许同一时刻多条事件，顺序由 `id` 决定。

## 五、功能以外的硬约束

| 约束 | 说明 |
| --- | --- |
| 运行环境 | 单进程 + SQLite（标准库自带），**零新增依赖** |
| 内核纯度 | 内核代码里零场景词汇；词表随场景只增不改 |
| 时间语义 | `tick` 是业务时间，`recorded_at` 是入账时间；两者不同步是正常的 |
| 无外部副作用 | M1 不通知任何人、不调用外部接口、不用 LLM |
| 测试 | 一条命令跑全部测试；测试先于实现写 |

## 六、验收要求

验收分四组。**A 组是闸门，不通过就不进 M2。**

### A 组 · 判据 J6 五条（闸门）

**A1 状态重建**

- 做法：写一段事件流，中段拍一张快照，继续写事件；对若干时刻执行 `replay(tick)`；
- 通过：重建出的指标全集与当时逐字段相等，一个字段都不差。

**A2 审计链**

- 做法：构造"目标 → 拆解 → 选择 → 预测 → 执行 → 观测"的完整链路，对最终观测执行审计上溯；
- 通过：能回到最初的目标，且链路上每一环都在（含候选集、各候选当时账目、排序规则）。

**A3 重放一致性**

- 做法：同一段事件流重放两次，比较两次结果；
- 通过：逐字节一致。
- 说明：这一条要求所有投影是**确定性**的——不许依赖当前时间、随机数、字典遍历顺序、外部接口。

**A4 断裂降级**

- 做法一：抽掉链路中间的一条事件后重放；
- 做法二：把某条事件的 `caused_by` 指向一个不存在的事件；
- 通过：系统**报错退出或输出降级报告**，并明确指出断在哪里。**静默返回半条链 = 失败。**

**A5 误差不落库**

- 做法：检查 `sqlite_master`，再对运行时数据库做一次全文检索；
- 通过：不存在任何误差列或误差表；库里检索不到"误差/偏差"这类派生结果。

### B 组 · 契约测试（必须全过）

**B1 事件不可改**

- 做法：直接对 `events` 表执行 UPDATE 与 DELETE；
- 通过：数据库拒绝，原记录不变。

**B2 重放只读**

- 做法：重放前后比对事件表行数与最大 id、以及数据库文件的内容哈希；
- 通过：完全一致。重放不产生任何新记录。

**B3 单一写入入口**

- 做法：检查代码——写 `events` 表的 SQL 只允许出现在一个模块里；
- 通过：除该模块外零处写入语句。这条用脚本检查，不靠人工看。

**B4 写入校验**

- 做法：尝试写入非法 `type`、非法 JSON、指向不存在事件的 `caused_by`；
- 通过：三种情况都被拒绝，且库里没留下半条记录。

### C 组 · 能力测试（必须全过）

**C1 换知识版本重算历史误差**

- 做法：同一条预测，先在知识 A 版本下算误差；改成知识 B 版本后重算；
- 通过：历史误差**按冻结的预期不变**（快照语义），而新生成的预测用新版本。两条同时成立才算过。

**C2 样本量随结果返回**

- 做法：查询方法账目；
- 通过：平均效果与样本量一起返回，且样本量正确。

**C3 目标达成与预测误差是两个投影**

- 做法：构造"预测在带内、但目标未达成"的情形；
- 通过：两个投影给出各自的结论，互不干扰。

### D 组 · 边界测试（必须全过）

**D1 空账本**：没有任何事件时，重放与三条投影不报错，返回空结果。

**D2 无快照**：只有事件、没有快照时，重放从起点开始且结果正确。

**D3 同一时刻多条事件**：确认顺序完全由 `id` 决定，与 `tick` 相同无关。

**D4 未来时刻**：对一个还没有数据到达的时刻执行重放，返回该时刻已有的状态，不报错。
