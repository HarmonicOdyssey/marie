# 玛丽（MARIE）

> **用通用、可复用、尽可能灵活的原子化实体，低成本、快速构建不同场景下的复杂系统。**

---

## 这是什么

玛丽是一套**构造架构**，不是一个应用。它解决的问题是：给定一类场景，怎么用同一套积木快速搭出那个系统。

搭出来的系统做一件事：接收可量化的目标，把目标拆解到可观测的指标上，持续选择方法、执行方法、观测结果、忠实记账、报告误差，让环境不断满足目标、或尽可能向目标靠拢。

**系统不替任何人决策。** 它执行给定的逻辑、记账、对账、报告，把判断留给该做判断的人（在无人场景中，留给场景指定的外部流程）。

---

## 适用范围

三个条件同时满足才适用：

| # | 条件 |
| --- | --- |
| C1 | **目标可量化**（单值，或向量加红线） |
| C2 | **环境有可量化指标**，目标是这些指标的一部分或能拆解到它们上 |
| C3 | **持续运营**（一次运行结束后还会再次组装） |

**目标可达与不可达都在范围内。** 可达成是特例，不可达成是常态——因此收敛判据取误差随时间的曲线，而不是"某天是否达标"。

---

## 四件架构本体

| 本体 | 说明 |
| --- | --- |
| **原子实体（MARIE）** | 以**指标**定义的组件：被激发、可授权、基于存储、推理、实体。不持有长期状态，行为 = 组件 × 世界 |
| **认知层**（可修订） | 由原文提炼的概念与关系构成的知识图谱。"世界通常是什么样的" |
| **实践层**（只追加） | 事件账本 + 快照。"当时究竟发生了什么" |
| **逼近循环** | 来自预测加工模型：**预测 → 观测 → 误差 → 修正**。误差在哪一层被处理掉，取决于那一层有没有手段 |

认知与实践的关系、以及"记忆到底怎么存"，见 **[核心/10-认知与实践](核心/10-认知与实践-记忆的设计.md)**——那篇从设计哲学推到数据结构，不需要先读别的。

---

## 五条最容易被误解的地方

| 误解 | 实际 |
| --- | --- |
| 自然语言是"不可量化"的 | 自然语言本身就是对现实世界的一次量化与压缩。要检验的是**粒度与稳定性**，不是"能不能量化" |
| 系统会预测未来 | 系统不做因果推断、不做长程推演。预测的职责由知识承担，它只逐时刻对账 |
| 玛丽会替人拍板 | 她只做一件事：**选择一个方法并执行**。是"自己操作"还是"向人提建议"，由方法定义里的**执行体**决定，属于知识 |
| 报告 = 报警 | 分三层：**入账**留全部事实、**报告**让人知道有什么变化、**上报**只请人做只有人能做的事 |
| 缺口是"做不了" | 缺口**有地址**：数据 / 知识 / 方法 / 结构 / 组件五类，都指到具体位置 |

## 关键设计决议

| 决议 | 一句话 |
| --- | --- |
| **一次运行一张图，用完即散** | 玛丽是知识与经验的产物。运行结束后知识与经验可能已变，所以每次从最新知识重新组装 |
| **账本只追加，永不修改、永不合并** | 审计、时序、序列学习都建立在它之上。这条是红线 |
| **认知层可修订，靠合并计数聚热点** | 它存"通常怎样"，不存"某一次"——执行实例只在账本 |
| **误差不落库** | 只存事实（观测值、冻结的预期）。误差永远现算，所以知识修正后历史可以重算 |
| **知识只追加版本** | 未比对的预测按生成时绑定的版本对账；旧版本永久保留 |
| **执行期间不修改知识源** | 铁律。知识的演化发生在内核之外 |
| **授权只有一个作用面** | 存储里的数据内容。看得到什么就等于能用什么 |
| **上报的触发条件是缺口** | 不是误差大小。报告的永远是"我缺什么" |

## 当前状态

**架构设计阶段，尚未开始编码。**

首个场景选定 **项目管理**（拆解开发任务、排期、每日收发日报、跟踪进度、报风险）。下一步是三期 POC，工期 11–15 个有效工作日：

| 阶段 | 内容 | 闸门 |
| --- | --- | --- |
| M1 | 账本 + 认知层接口 | 重放一致性、审计链、断裂降级、误差不落库 |
| M2 | 环路 + 场景绑定 + 日循环 | 20 节拍的误差曲线、正常运转不推送 |
| M3 | 第二个场景 + 复用率 | 内核零改动、复用率数字 |

> **一个要诚实说明的边界**：M1–M3 验证的是"这套架构成立"，**不是**"对企业有用"。后者的前提是真实知识源接入（RAG），那是 POC 之后的下一步。
