# 05 · 建模玛丽

> **"从数据里长出知识"这件事，本身就是一个玛丽。**
> 它不需要任何新机制——它用的就是[玛丽那条循环](02-玛丽的循环.md)。

---

## 一、为什么它是一个玛丽，而不是一个新模块

上一版设计里，"发现新知识"被当成架构之外的一件事，需要另开一套机器。**那是错的。**

它严丝合缝地落回玛丽的定义：

```
建模玛丽
  输出指标    所产出知识的**解释率**（或残差）
  可用方法    四项检查（第二节）
  对账        换个方法之后，解释率升了吗？   ← **可测**
  缺口        解释率升不上去 → 上报"这块我撑不住"
```

**它满足玛丽的全部条件**：目标可量化 ✅、有可测指标 ✅、持续进行 ✅。

**而且它把"维护玛丽"从系统外的手工活，变成了一个可度量的循环。**

---

## 二、它的目标：**所有经验都可以被知识解释**

### 什么叫"被解释"

**一个决策**被解释，需要**两件事同时成立**：

| # | 条件 |
|---|---|
| **1** | **量齐**：有一条知识，它要的**输入量与输出量**，在这次发生里都被观测到了 |
| **2** | **残差可接受**：用它算出来的残差，在可接受范围内 |

### "解释不了"分三种，各指向不同的动作

| 情形 | 含义 | 该做什么 |
|---|---|---|
| **没有知识覆盖** | 我们**不知道该看什么** | **补知识** |
| **有覆盖，但预期不符** | 知识**错了** | **修知识** |
| **两者都不对** | 算法的形状错了（输入量本身选得不对）| **改算法** |

### 度量

```
解释率 = 能被解释的决策数 ÷ 总决策数
```

**可算、可逼近、可跨时间比较。**
**而"解释不了的那部分"就是知识地图上的空白。**

**注意"多对多"带来的一个修正**：一次复杂的经验，**可能需要多条知识联合才能解释**——单看哪一条都不够。所以"被解释"的判定要允许"多条知识合起来覆盖"。

---

## 三、它的方法 = 四项检查

**就是 [04](04-知识该长什么样.md) 里那四条判据**，做成可执行的检查：

| # | 检查 | 产出 |
|---|---|---|
| **1** | 输入量**可观测**吗 | "路程没有任何观测来源" + 位置 |
| **2** | 输入量**有手段**吗（分工类）| "排队时长没有任何方法能影响它" + 位置 |
| **3** | **残差有结构**吗 | "残差与『天气』相关 −0.52" + 位置 + 样本量 |
| **4** | 输入量**冗余**吗 | "加油时间完全决定运输时间" |

**换个方法之后解释率有没有升——这就是它的对账。** 所以四项检查不是拍脑袋的规则，而是**它的候选方法**。

---

## 四、**报警 vs 判决** ← 本篇的核心

> ### **判决 = 系统自己改知识。**
> ### **报警 = 系统只把"哪里不对"指出来，改不改、怎么改，人定。**

### 四类检查各自的行为

| 检查 | 系统**做** | 系统**不做** | 人**做** |
|---|---|---|---|
| **1 不可观测** | 报出"这个量没有观测来源"+ 位置 | 不说"去掉它" | 补登记，或决定改算法 |
| **2 没手段** | 报出"这个量没有方法能影响它"+ 位置 | 不判断该不该派它 | 判断是"该发现方法"还是"该合并" |
| **3 残差有结构** | 报出相关量 + 位置 + 样本量 | 不说"加它进去" | 判断它是不是构成项 |
| **4 冗余** | 报出"B1 完全决定 B2" | 不合并、不说留哪个 | 决定合成一个还是换表达 |

**能给的**：**事实 + 位置 + 线索**。
**不能给的**：**该不该改 + 改成什么**。

### 判据 3 的具体样子

```
位置     拆解「单趟周期 = 行驶 + 装载 + 卸载 + 排队」@v2
事实     残差 4.6 min，与「任务时段电量」相关 −0.52
样本     3,180 个节拍
最强的话 「可能漏了这一项」

不能说：
  ✗ 「电量是原因」——也可能任务重的班次电耗大（方向相反）
  ✗ 「该加进拆解」——相关 ≠ 构成
  ✗ 「加在哪一层」
```

### 最能说明问题的一处：同一条报警有**相反的两种含义**

```
报警：量「排队时长」被派给了一个玛丽，但没有任何方法能影响它

含义 (a)：它不该被派出去 —— 没人能对它动手
含义 (b)：该有方法，只是还没被发现 / 还没登记

系统分不清是哪种
  → 只能说「它目前没有手段」，不能说「别派它」
```

### 为什么不能判决（四条，按硬度排）

| # | 理由 |
|---|---|
| **1** | **语义承诺数据给不了**——"这到底是不是构成关系"是人的判断 |
| **2** | **同一条报警可能有相反的含义**（上面那个例子） |
| **3** | **假警报存在**——`Var(B2\|B1)≈0` 也可能是"两者都被第三个量锁定" |
| **4** | **判决要承担后果**——改错了，是它在用错知识指导实践。**而承担后果的是人** |

**第 4 条与早已定下的纪律对上**：**执行期间不修改知识源，改知识必须人确认。**
**所以"只能报警"不是能力不足，是同一条纪律的延伸。**

### 那报警有什么用

**最花时间的不是"想清楚怎么改"，是"知道该去哪看"。**

```
21,600 车·班、3 条路线、40 辆车
  → 拆解不合理，人不可能靠扫出来
  → 系统把范围缩到「这个拆解的第三项」+ 证据 + 样本量
  → 人只需要判断这一处
```

**报警本身也是一个动作，所以也记进经验。**
于是"这个报警我关掉了""我改成这样了"都留痕——**报得准不准，以后也能被统计。**

**这没有离开轨道**：还是"决策 → 经验 → 反省知识"。

## 五、它的两个诚实限制

| # | 限制 |
|---|---|
| **1** | **它只能检验"已声明的"，发现不了"未声明的"。** 残差能告诉你"漏了『电量』这一项"，但**告诉不了你"该拆成哪几项"**——那是人给的 |
| **2** | **它调的是参数和条件，不是结构。** 改拆解的结构（换一种表达方式）**必须人来** |

**这两条不是缺陷，是边界。** 而它们对应到[缺口](08-组装与缺口.md)：**有一种缺口叫"我们连该看什么都不知道"**——那就是需要人的地方。
