## 一句话

> **只有两样东西要存：**
> **「经验」——实测数据，只加不改，它是唯一不可重建的东西。**
> **「知识」——程序里用来计算的算法与参数，能改、旧版留着。**
>
> **知识的形状是「输入量 → 输出量」；对账就是拿实测输入重算，与实测输出比。**
> **而"从数据里长出知识"这件事，本身就是一个玛丽。**

### ⚠️ 一个用词澄清（很要紧）

**别把"知识""经验"读成人类的措辞——它们是机器里的机制。**

我在这上面错过好几次：把**机器里的机制**读成**人类的措辞**，
于是凭空造出"归类""多解读""另一个现实"这些**根本不存在**的东西（见[附录C §三](附录C-差异与待办.md)）。

## 三句话把设计说完

**① 为什么必须分两样。**
记忆被用在两件**要求相反**的事上：支持判断要**概括**，接受审计要**精确**。
同一结构不可能同时满足 → **必须分开**。

**② 知识凭什么算数。**
一条知识如果**无法被推翻**（"看情况处理"），它就**不是知识**，只是注释。
而系统一旦允许这类东西进来，它们会迅速填满知识库——**因为它们永远正确、永远不改、永远不产生缺口。**

**③ 怎么判断它管用。**
**归因没那么重要。** 一万次导向同一个结果，就够用了。
所以系统的首要任务不是"做因果"，而是**把每次实践的输入记全**——
因为输入记全 + 重复够，规律才成立**且你知道它在什么范围内成立**。

**④ 一次实践里做了很多次决策，怎么厘清？**
**不用厘清。** 程序**不解读，它重算**：拿**当次的实测输入**算出预期，与**实测输出**比，剩下的才是残差。
**"意外"的影响通过"输入变了"自动进入**——程序不需要理解意外。

## 三个必须显形的"分不清"

设计的目标不是消除它们（消除不了），是**让它们显形**：

| # | 分不清 | 若被静默吸收 |
|---|---|---|
| **1** | **没观测到 ≠ 没效果** | 数据没采到 → 记成方法没用 → **有效方法被永久放弃** |
| **2** | **多个动作重叠 → 效果分不开** | 记成某一个的功劳 → **功劳乱分** |
| **3** | **条件覆盖窄** | 规律看着成立 → **出了那个范围就失效而你不知道** |

## 一条贯穿全篇的纪律

> **系统只报警，不判决。**
>
> **报警** = 指出"哪里不对"（位置 + 事实 + 线索）。
> **判决** = 自己改知识。**不做。**

**理由中最硬的一条**：改知识要承担后果，**而承担后果的是人**。
这与 marie 早就定下的"执行期间不修改知识源"是**同一条纪律**。
