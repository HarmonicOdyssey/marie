# 09 · 知识图谱与原文片段

> 这一篇回答一件事：**玛丽怎么从"文档"拿到"怎么做"**，以及**知识和方法在这套存储里怎么放**。
> 它是 [06 图结构](06-图结构.md) 的补充——06 讲"图怎么搭"，这一篇讲"**这一层是给谁用的**"。

---

## 一、这一层是干什么的

```
知识图谱 + 原文片段  =  一个库

玛丽在两类时刻查它：
  ① 要【拆解目标】时     →  "A 该摊成什么？"       → 得到拆解的方法
  ② 要【选可执行方法】时  →  "这种情况该做什么？"   → 得到可执行的方法
```

**而这两个查询都是同一个入口：给一个「量」，返回与它有关的东西。**

```
查「当班圈数」→ 返回：能拆它的方法
查「脱产时间」→ 返回：能改善它的方法
```

### 最要紧的一条：**消费者是程序，不是人**

| | 人 | 玛丽 |
|---|---|---|
| 看一段文字 | 就懂了 | **算不了** |
| 要什么 | 内容 | **结构 + 执行体** |

**所以这个库必须同时有两条腿**：

| 腿 | 给什么 |
|---|---|
| **原文片段** | 细节（"规程到底怎么写的"）|
| **图谱** | 结构（"这条涉及哪些量、条件是什么、谁去执行"）|

**两条腿在检索上是平级的**——不是"图谱为主、原文为证"。

## 二、三个词别混

| 词 | 是什么 | 例 |
|---|---|---|
| **量** | 可观测、可取值的 | 脱产、当班圈数、电量 |
| **动作** | **可执行的一件事** | 错峰充电、点检、保养 |
| **知识** | **一条可检验的断言** | "遇恶劣天气，车速降 20%" |
| **经验** | 实测数据 | 这次脱产 52 min |

### 「方法」= 「动作」

**而拆解也是一种动作。** "把当班圈数拆成『脱产 ÷ 周期』"本身就是一个选择，有优劣：

```
动作：拆解「当班圈数」
  候选拆法 A：圈数 = (480 − 脱产) ÷ 单圈周期
  候选拆法 B：圈数 = 充电脱产 + 维保脱产 + 行驶……
```

**所以"拆解的方法"和"可执行的方法"是同一类东西。**
**而 RAG 查的永远是「知识」——「方法」是被选出来的那个动作。**

## 三、复盘：一篇 SOP 进来之后会发生什么

### 素材

```
《矿区无人车调度作业规程 V1.2》

2.1 单圈行驶里程约 3.5 公里，满载运行时单圈耗电约 5%。
2.2 电量低于 25% 时必须前往充电桩。
2.4 遇恶劣天气（雨、雪、雾），车速降低 20%。
3.1 每 7 天点检一次，每 30 天保养一次。
```

### 第 1 步 · 标准化 → 信息单元

```
unit_001  无人矿车单圈行驶里程约 3.5 公里；无人矿车满载运行时单圈耗电约 5%。
unit_002  无人矿车电量低于 25% 时必须前往充电桩。
unit_003  无人矿车遇恶劣天气（雨、雪、雾）时，车速降低 20%。
unit_004  无人矿车每 7 天点检一次；无人矿车每 30 天保养一次。
```

### 第 2 步 · 抽取 → 图谱

**词汇（都是 `g`——动作和对象混在同一类型里）**

```
对象类：(g:无人矿车) (g:单圈行驶里程) (g:单圈耗电) (g:电量) (g:充电桩)
        (g:恶劣天气) (g:车速)
动作类：(g:前往) (g:降低) (g:点检) (g:保养)
```

**断言（都是 `f`——规律和指令混在同一类型里）**

```
(f:无人矿车单圈行驶里程约3.5公里，满载运行时单圈耗电约5%)   {m: declarative}
(f:无人矿车电量低于25%时必须前往充电桩)                    {m: imperative}
(f:无人矿车遇恶劣天气时车速降低20%)                        {m: conditional}
(f:无人矿车每7天点检一次，每30天保养一次)                    {m: imperative}
```

**关系**

```
每一条 f --11 参与--> 它涉及的那些 g
每一条 f --来源--> 对应的 unit
```

> **注意**：`3.5`、`5%`、`25%`、`20%`、`7 天`、`30 天` **全都不进结构**，它们在 `f.d` 那段文字里。

### 第 3 步 · 玛丽来问（这才是重点）

**问① 我要拆解「当班圈数」**

```
去图谱里找涉及"当班圈数"的断言
→ 没有。SOP 通篇不提"当班圈数"
→ **返回 0 条**
→ 只能报缺口："不知道怎么拆解 当班圈数"
```

**问② 我要改善「脱产时间」**

```
去图谱里找涉及"脱产"的断言
→ 没有直接说"脱产"的
→ 但能间接找到 (f:…每7天点检一次，每30天保养一次)
   —— 点检和保养都会产生脱产
→ 玛丽知道"有点检和保养这两件事"
→ **但算不出它们各占多久**（SOP 没给耗时，值也不抽）
→ 报缺口："知道有这两个动作，但不知道影响多少"
```

**问③ 电量低于 25% 要去充电——这个玛丽能用**

```
找到 (f:电量低于25%时必须前往充电桩) {m: imperative}
→ 读成一条【约束】：电量 ≥ 25%
→ 放进规划算法当约束
→ 规划不出充电时机时 → 无解 → 上报
✅ 这条**能用**
```

**问④ 耗电 5%——玛丽能用吗**

```
找到 (f:…单圈耗电约5%) {m: declarative}
→ 但 5% 是文字里的一个字符序列
→ 玛丽要算"还能跑几圈"，就得**去解析这段文字**
❌ **这条用不了**
```

### 第 4 步 · 跑起来之后

```
玛丽用上 5% 那条（假设解析出来了）
→ 实测：一圈实际耗 5.8%
→ 残差 +0.8%
→ 报警："这条知识抽自 2.1 节，偏差 0.8%，样本 3180"
→ 人 → 改 SOP → 重抽 → 新版本
```

### 第 5 步 · 版本与同步

```
重抽之前：unit_001 的内容哈希 = a1b2c3
         知识节点记着："我抽自 a1b2c3"

SOP 改了 → unit_001 哈希变成 d4e5f6
→ 核对：知识记的是 a1b2c3 ≠ d4e5f6
→ **报「待重抽」**
```

## 四、复盘暴露的六个问题

### 问题 1 · SOP 给的是"参数与局部规则"，玛丽要的是"目标怎么拆"、"这个动作影响多少"

```
SOP 里有：  单圈耗电 5%      （一个参数）
SOP 里没有：圈数 = (480−脱产) ÷ 周期   （拆解）
SOP 里没有：点检耗时 1 小时            （影响）
```

**结论：文档抽取覆盖不了玛丽的全部知识需求。**
拆解知识多半来自**数据或人**，不是文档。

### 问题 2 · `f.d` 是自然语言，玛丽算不了

HOH 明令"严禁提取具体的值"（参数值、数值、指标）。

**但那条禁令的理由被搞错了。** 它想防的是**"值做成节点"会造成伪共享**（同一个 `22` 连向无数不相干的事实）——**而不是"值不该被记录"。**

**所以处置是**：

```
值不做【节点】  ✅  （会伪共享）
值做【属性】    ✅  （挂在那条知识上）
```

```
(f:…单圈耗电约5%) {m:declarative, 参数:{耗电:0.05, 里程:3.5}}
```

**而这份参数是【原文的投影】，不是正本**——改它要先改原文（见第六节）。

### 问题 3 · `f` 里同时装着"规律"和"事件"，而它们在 marie 里分属两样东西

```
(f:遇恶劣天气车速降20%)   →  普遍规律  →  **知识**
(f:3月5日7号车发生故障)    →  一次发生  →  **经验**
```

**而 `m` 分不开它们**：`declarative` 两种都盖（既盖"规律"也盖"已发生的事"）。

**而文档里两种都会出现**（手册写规律，工单写事件）。

**处置**：`f` 上要有一个属性区分**普遍 / 一次**。

### 问题 4 · `11 参与` 分不出方向

```
(f:…单圈耗电约5%) --11--> (g:单圈耗电)     ← 耗电是【算出来的】
(f:…单圈耗电约5%) --11--> (g:满载)         ← 满载是【条件】
```

**同样是"参与"，一个是要算的量，一个是输入条件。** 玛丽必须分得清——否则它不知道"这条知识能算出什么"。

### 问题 5 · `g` 既是"对象类别"又是"动作"

```
(g:无人矿车)  ← 对象
(g:点检)      ← 动作
```

**玛丽"选方法"时要的是后者。** HOH 没区分，得加一个属性。

### 问题 6 · 约束没有"量的条件"这个形状

```
原文：      (f:电量低于25%时必须前往充电桩) {m:imperative}
规划算法要：电量 ≥ 25%
```

**中间缺一步转化**——从一条祈使事实，到一个可判定的约束表达式。

**处置**：抽取时要把它落成 `量 + 比较符 + 值`。
**判据**：**落不成的，就不算约束**——那它是"看情况处理"，进缺口。

## 五、结论：要不要新的节点类型

> ## **不需要。**

```
方法（动作）  =  g（动词类普遍概念）
知识（断言）  =  f（事实）
```

**但需要给已有的类型加几处属性 / 边：**

| 需要 | 加在哪 | 对应问题 |
|---|---|---|
| 区分**普遍规律 / 一次发生** | `f` 的属性 | 问题 3 |
| 表达**输入量 → 输出量**的方向 | `f` 上的边 | 问题 4 |
| 区分**对象 / 动作** | `g` 的属性 | 问题 5 |
| **参数**（作为原文的投影）| `f` 的属性（**值不做节点**）| 问题 2 |
| **版本链** | `f` 上的「取代」边 | 第六节 |
| **指向执行体** | `f` 上的边 | — |

**我先前说"知识要单立一类节点"，是错的**——理由（HOH 装不下参数）在"参数的正本在原文"这条被指出之后就塌了。**参数本来就该在原文里。**

## 六、知识的来源与变更

### 三类来源，"改的动作"落在不同地方

| 来源 | 正本在哪 | 改的路径 |
|---|---|---|
| **文档抽来的** | **原文**（SOP、手册）| 改原文 → 重抽 |
| **数据长出来的** | **知识本身**（没有原文）| 拟合 → 候选 → 人确认 |
| **人直接给的** | **知识本身** | 人改 |

### 一条硬理由：为什么"文档来源"必须先改原文

> **SOP 是给人执行的。**
> **如果机器的知识和 SOP 不一致，那就是人和机器在按两套规则干活。**

**这不是权限问题，是"同一个组织不能有两套规程"的问题。**

### 所以经验**从不直接改知识**

```
经验（实测偏离）
   ↓ 对账
残差
   ↓ 稳定且大
报警："这条知识抽自 2.1 节，偏差 0.8%，样本 3180"
   ↓
人 → 改 SOP → 重抽 → 新知识版本
```

**而"实测"永远不进知识。**
知识里只有一个数（`5%`）；实测（`5.8%`）在经验里；**"差 0.8%"是每次对账现算的，不存。**

### 同步怎么保证

```
原文单元  带 content_hash
知识节点  记 "我抽自 hash = a1b2c3"

原文改了、知识没重抽  → hash 对不上 → **报「待重抽」**
知识改了、原文没改    → **不可能发生**（知识只能通过"重抽"或"拟合+确认"产生新版本）
```

### 一处需要注意的分界

> **知识可以比原文更细，但不能与原文矛盾。**

```
SOP：  "遇恶劣天气，车速降低 20%"
知识：  车速 = 基准车速 × 0.8，当 天气 ∈ {雨, 雪, 雾}
        + 补上"基准车速"的定义          ← 更细，✅ 允许

经验：  实测降 12%，不是 20%
知识：  要把 20% 改成 12%               ← 和原文矛盾 → ❌ 必须改原文
```

**SOP 是给人读的，不必精确到能算；机器必须精确。所以"补细节"是抽取的正当工作，而"改结论"不是。**

## 七、检索与变更，是两个不同的问题

| | 结论 |
|---|---|
| **检索上** | **平级**。图谱与原文都是可查的内容，两条路各自能召回 |
| **变更上** | **路径唯一**。知识的变更只能"从原文重抽"或"拟合 + 确认"，**不能就地编辑** |

**说"没有主次之分"，说的是检索；说"先改原文再改知识"，说的是变更。两件事，不冲突。**

## 八、三条硬要求

### 要求 1 · 「适用条件」的判定必须在**下发之前**

```
召回不到  →  报缺口（"我不知道怎么拆解 A"）   → 无风险
召回错了  →  选了不适用 / 无效的方法          → **会真的做错事**
```

**向量相似度给的是"看起来相关"，不是"条件满足"。**
**流程必须是"先检索、再判定条件"，两步不能合成一步。**

### 要求 2 · **检索结果必须入账**

**"这次决策依据了哪几条知识"是我们要记的**（见 [03 §五](03-咬合.md)）。
**而方法是从库里查出来的，那"查到了哪几条、选了哪一条"就是依据本身。**

**不记** → 事后无法回答"这条方法被用过多少次、效果如何" → **经验反哺没有原料**。

### 要求 3 · 返回集的形式由**查询方**声明

```
【拆解】我要拆解「当班圈数」
   → 必须给出**一个确定的拆法**（不能同时用两种，否则子指标重复计）

【选方法】我要改善「脱产」
   → 必须给出**一组候选**（否则没得比较）
```

**同一张图、同一个检索键，两种消费方式的期望相反。**
**所以"给几条"由查询方说，不能由存储层定。**

## 九、这一篇纠正的东西

| # | 我之前说的 | 改成 |
|---|---|---|
| 1 | **知识要单立一类节点** | **不用**。方法 = `g`，知识 = `f`，只加属性 |
| 2 | HOH"装不下可被经验修改的东西" | 它装不下的是**参数与版本**；而**参数的正本在原文**——这一点我说反了 |
| 3 | 知识节点同时装"原文值 + 实测值" | **不存在**。实测永远不进知识；差值是对账现算的、不存 |
| 4 | 玛丽"带偏差决策" | **不做**。玛丽忠于知识；偏差只用于报警 |
| 5 | "先把偏差带进决策"这个选项 | 它假设"实测能成为知识"，**前提就是错的** |
| 6 | 情态删除 | **恢复**（沿用 HOH 三值）|
| 7 | 「红线」是独立概念 + 有"硬度属性" | **红线就是约束**；硬度属性**删掉**（约束不满足 → 规划无解 → 那是算法的行为）|
