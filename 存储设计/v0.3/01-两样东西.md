# 01 · 两样东西

> 由[必然结论一](00-为什么.md)推出：**只有两样东西要存。**

---

## 一、一个用词上的澄清（很重要）

**别把这里的"知识""经验"读成人类的措辞。它们是机器里的机制。**

| 词 | 它实际是 | **不是** |
|---|---|---|
| **知识** | **程序里用来计算的算法与参数** | 人类写的规则条文 |
| **经验** | **实践过程中收集到的实测数据**（估了 5%，实际 8%，以及当时的天气、路况、载重……）| 人的经历、心得 |
| **方法** | **程序能执行的一个动作** | 一条建议 |

**为什么这条要先说**：我在这上面错过好几次——把"机器里的机制"读成"人类的措辞"，
于是凭空造出"归类""多解读""另一个现实"这些根本不存在的东西（见[附录C](附录C-差异与待办.md)）。

---

## 二、经验：发生了什么

**只加，不能改。**

```
（发生#4711）{发生: 14:20, 记账: 14:20}
    路程 = 4.2 km       ← 实测，绕路了（本来 3.5）
    载重 = 90 t
    天气 = 雨
    耗电 = 7 %           ← 实测
```

**为什么不能改**：**它是唯一不可重建的东西。**

- 原文丢了可以重抓
- 知识错了可以重编
- **只有"当时究竟发生了什么"丢了就永远丢了**

**写错了怎么办**：再写一条更正记录。**不许覆盖。**

### 经验里只有一种记录

```
一次发生 = 一组同期的（量, 值）
```

**它可以顺带带上：依据了哪条知识、选了哪个动作、当时算出来的预期是多少。**
但那只是它的附加字段，**记录本身的形状是"那些量当时的值"。**

**派生量不存**：排队 40 分钟 = `开始充电 − 派往桩3`，**算出来的，不存**。

---

## 三、知识：我们相信什么

**能改，旧版本留着。而它的形状是：**

```
知识 = 一个函数：输入量 → 输出量 + 参数
```

| 算什么 | 输入量 | 输出量 |
|---|---|---|
| 一圈耗多少电 | 路程、载重、天气、车况 | 耗电 |
| 充一次要多久 | 起始电量、桩功率、温度 | 充电时长 |
| 目标 A 摊成子指标 | B1、B2…… | A |
| 充电顺序怎么定 | 各车状态 | **它预期的结果** + 它选出的顺序 |

**不分拆解 / 方法 / 估算——一种表达**（详见 [04](04-知识该长什么样.md)）。

**它和经验的根本区别：**

| | 经验 | 知识 |
|---|---|---|
| 是什么 | 事实 | 诠释（算法与参数）|
| 同一件事再发生 | **新增一条** | **合并**（不新增知识，只积累证据）|
| 能不能改 | ❌ | ✅ |
| 能不能删 | ❌ | ✅（标记失效）|
| 谁是唯一不可重建的 | **它** | 不是（可从经验重编）|

## 四、图上只放"相同即同一"的东西

| | 问的是什么 |
|---|---|
| **归一** | "测距雷达"和"前置防撞包"——**名字不同，是不是同一个东西？** |
| **节点还是属性** | 两条记录都有"22"——**名字相同，是不是同一个东西？** |

**答案决定它上不上图：**

> **实体名相同 → 是同一个东西 → 做节点。**
> **值相同 → 不代表什么 → 做属性。**

**为什么值不能做节点**：如果"22"是一个节点，它会指向无数**完全不相干**的记录——它们之间本来毫无关系，只因为数值相同就被连成一片。**这叫伪共享。**

**而"7号车"出现在两条记录里，那确实**是同一个东西**，共享是对的。

---

## 五、网格：（对象 × 时间）

**经验里的每一条记录，都落在两个坐标上：**

```
                对象（7号车、3号桩、1号线、整个车队……）
                  │
                  │    每个格子 = "某个对象在某个时刻"
                  │
                  └──────────────────────→ 时间
```

- **发生**落在格子上（那些量当时是多少、做了什么）
- **知识 = 关于这些格子上的规律的陈述**

**"落不到网格上" = 无法在某个具体的（对象、时刻）上被核对。**

| | |
|---|---|
| ✅ "耗电 = f(路程, 载重, 天气)" | 能落到——**能找**符合条件的具体对象与时刻 |
| ❌ **"看情况处理"** | **落不到**——没有任何可核对的内容 |

**落不到的东西不进知识，但可以进缺口。**

---

## 六、世界：**可见性标记**，不是"另一个现实"

**最笨的实现是每个应用一套独立的数据库；"多世界"就是用同一套数据库去存，数据上标记可见给谁。**

| | |
|---|---|
| **是什么** | 数据上的一处**可见性标记** |
| **干什么** | 权限、不同用户、游戏内多个 AI、多场景复用 |
| **不是** | 不是"另一个现实"，不是对象，不是维度 |

**注意：知识是共用的**（同一套库），只是**可见性**不同。

**唯一要求**：**必须能"只看到一个可见范围"地查询**，而不是查完再过滤——**放到查询端过滤，它一定会在某个连接处静默漏掉。**

---

## 七、本篇的结论

| # | 结论 |
|---|---|
| **1** | **知识 = 程序里的算法与参数；经验 = 实测数据。** 别读成人类的措辞 |
| **2** | 只有两样：**经验**（只加）、**知识**（可改，留版本）|
| **3** | 一次发生 = **一组同期的（量, 值）** |
| **4** | 图上只放**相同即同一**的东西；值做属性 |
| **5** | 一切落在**（对象 × 时间）**上；落不到的不进知识 |
| **6** | **世界 = 可见性标记**（同一套库，标可见给谁）|
