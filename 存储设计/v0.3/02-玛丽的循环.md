# 02 · 玛丽的循环

> **这是轨道。** 后面所有设计都必须落在这条轨道上；
> 凡是需要"另开一套机制"的想法，先怀疑它。

---

## 一、一个玛丽在做什么

```
① 上游下达目标指标 A
② 玛丽按【知识】把 A 表达成 B1、B2……
③ 观测 / 收到 B1、B2…… 的值
④ 与目标比 → 有误差？
⑤ 有 → 按【知识】选择合适的方法去消除误差     ← **这就是一次决策**
⑥ 把这次决策的结果记成【经验】
⑦ 经验反过来强化知识的可信度，或"反省"知识是否不可靠、甚至错误
```

**②④⑤是内部的，③⑥是对外的，⑦是闭环。** 一圈走完，知识要么更可信，要么被推翻。

---

## 二、拆解：把目标表达成子指标

**拆解 = 按知识把上游下达的目标指标 A，表达成其他指标 B1、B2……**

```
圈数 = (当班时长 − 脱产时间) ÷ 单圈周期
       ↑            ↑              ↑
       A           B1             B2
```

**"怎么表达"完全由知识决定。** 架构只提供"表达"这个**位置**，不预设形式：

| 表达形式 | 例 |
|---|---|
| 公式 | `A = (480 − B1 − B2) ÷ B3` |
| 配额 | `B1 ≤ 30 min` |
| 区间 | `B2 落在 [35, 38]` |
| 红线 | `B3 ≥ 15%`（破了要上报） |
| 别的 | 由知识决定 |

**一条质量要求**：**B1、B2……各占一个自由度。**
如果 B1 变了 B2 就被完全决定，那它们不是两个子指标，是同一个东西的两种写法。
（判据见 [04 知识该长什么样](04-知识该长什么样.md) 第五节。）

---

## 三、决策：一次方法的选择

**上一步算出"B1 离目标差多少"，这一步决定"做什么"。**

```
决策 = 在当时的条件下，从可用方法里选一个
```

**它的输入是"当时的状态"**（B1、B2 的值、以及别的条件），**输出是"选了什么"。**

**决策是一次具体的行为**，不是一条规则。规则在知识里，决策是这次实际做出的选择。

**为什么它要紧**：因为**它是知识与经验唯一的接触点**。一条知识有没有用、对不对，唯一的证据就是"依据它做的那些决策，结果如何"。

---

## 四、记录：把决策的结果记下来

**玛丽必须把决策的结果记成经验。** 记的东西见 [03 咬合](03-咬合.md)。

**为什么这一条不能省**：没有它，知识永远无法被检验——**系统就变成了一个只在执行、从不学习的机器。**

---

## 五、反省：经验反过来改知识

一圈走完之后，经验会给出三种信号：

| 信号 | 含义 | 该做什么 |
|---|---|---|
| **解释不了** | 没有知识覆盖这个情境 | **补知识** |
| **预期不符** | 知识错了 | **修知识** |
| **拆解有毛病** | 结构错了（漏项 / 冗余 / 不可观测 / 没手段） | **改拆解** |

**这三种信号都由"建模玛丽"去发现**，而且**它只报警、不判决**——见 [05 建模玛丽](05-建模玛丽.md)。

---

## 六、知识就是一个函数

**玛丽一路上用到的知识，形状是同一种：**

```
知识 = 一个函数：输入量 → 输出量   + 参数
```

| 算什么 | 输入量 | 输出量 |
|---|---|---|
| 一圈耗多少电 | 路程、载重、天气、车况 | 耗电 |
| 目标 A 摊成子指标 | B1、B2…… | A |
| 充电顺序怎么定 | 各车状态 | **它预期的结果** + 它选出的顺序 |

**不分拆解 / 方法 / 估算。** 分得越复杂，维护越麻烦、实现坑越多（详见 [04](04-知识该长什么样.md)）。

**唯一一个属性：「用来分工」** —— 有一类知识的输入量要**派给下游玛丽**，
那些量必须"**有人能对它动手**"。其余知识（估算法）没有这条要求：
天气没有手段，但它是耗电算法的正当输入。

**至于"怎么选方法"**：它可以是**算出来的**（各方法预期结果 + 限制 → 挑最优），不必是第三条知识。
真有"凭经验的选择偏好"，写在**那条知识自己的参数里**。

## 七、为什么这是轨道

回过头看这套东西的几个常见诱惑，**它们全都离开了轨道**：

| 诱惑 | 为什么不算数 |
|---|---|
| 造对照、做实验、证明因果 | 归因不重要（[00 §四](00-为什么.md)）；重复稳定就够 |
| 给每个子指标分配额度、设仲裁机制 | 那是**知识的内容**，不是架构该提供的机制 |
| 事后给经验"归类" | 决策那一刻已经知道依据了谁，不需要事后归类 |
| 把"发现"做成架构之外的新模块 | 它就是**一个玛丽**（[05](05-建模玛丽.md)）|
| 系统自动改知识 | 改知识要承担后果，**承担后果的是人**（[05](05-建模玛丽.md)）|
