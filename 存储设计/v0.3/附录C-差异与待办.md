### ⚠️ 第一件要知道的：HOH 不是**一个**设计，是**三代并存**

**同一个仓库里躺着三代互不兼容的方案。** 引用 HOH 时必须先说清是哪一代——**同一个 `14`，在三代里分别是「先于」「不存在」「属于」。**

| 代 | 在哪 | 数据库 | 关系 ID | 多世界 | 量化验证 |
|---|---|---|---|---|---|
| **企业代** | `ai_docs/business_logic/` | Neo4j + ChromaDB | **6 种**（1/2/3/11/12/13）| ✅ 三世界 | ❌ 无 |
| **MVP 代** | `mvp/` | **SQLite 单文件** + numpy 暴力搜索 | **7 种**（+ `14 先于`）| ❌ **明确砍掉** | ❌ 只有定性 |
| **酒馆代** | 根 `README.md` + `prompts/` | 未说明 | **另一套**（11/12/13/**14 属于 / 15 包含 / 16 实例**）| ✅ 有 | ✅ **5 样本 × 3 模型** |

**而"越接近能落地的那一代，砍得越多"**：

```
企业代：多世界 + 三分架构（Encoder / Inferencer / Mutator）
MVP 代：**砍掉多世界**（→ 单命名空间）、**砍掉三分**（→ 只留 Extractor）
        关系从 "43 号体系" 降到 7 种
酒馆代：只剩概念图 + 检索
```

**多世界被砍的理由是「企业特性，MVP 单用户」；何时加回，文档未说明（路线图里也没有）。**

## 三、前几版的错误清单（防止重犯）

**每一条都是"从文档措辞推导、而没有追问它在现实里是否成立"的产物。**

| # | 错误 | 教训 |
|---|---|---|
| **1** | 把"玛丽不直连存储"放大成架构契约（冻结接口、两个实现、38 项验收）| 原文只是"代码里别到处写 SQL" |
| **2** | 用**均值**聚合，把形状不同的实践链压成一个标量 | 均值在这里不是粗略，**是错** |
| **3** | 把**溯源做成一张表** | 它本该是一条边。"只记得最后一个来源"这个限制**只在表结构里存在** |
| **4** | 记**表层形式 + 出现次数** | 归一是语言模型做的，**它的产物里没有这个信息**——取不到的东西不要设计 |
| **5** | **`extraction_run`**（抽取作业元数据）| 三条理由全错 |
| **6** | **字符级偏移** | 一个概念在一段切片里有多种写法、多次出现，单个区间装不下；且要回原件还得反查一次——**鸡肋** |
| **7** | **缺口永久留存 + 反查补齐** | 过度设计 |
| **8** | 归一化"编辑距离 **且** 语义"双闸 | 为一个很窄的案例付**误并**的风险。真正该防的是"错并"，那靠**作用域边界** |
| **9** | 在知识里放"情态"字段 | 等于让知识自证可信 |
| **10** | "推不推"与"报告级别"**脱钩** | 于是"备查"照样被推，判据永远不成立 |
| **11** | **同一事实在两处记录，只改了一处** | 一处事实、两处存储，改一处必留错 |
| **12** | 用**正则文本扫描**去找"有没有针对某执行体的分支" | 那是**控制流属性**，不是文本属性 |
| **13** | **下标语义写错**（"最后 10 个节拍"写成"最后 10 次推送"）| 断言**永远不会为真** |
| **14** | **造了一个"主体"维度** | 它是"造对照"的产物，而"归因不重要"否掉了那个需求 |
| **15** | **把"归类"抬成一个概念** | 它被"决策时记下的依据"覆盖了 |
| **16** | **"认定""对齐"**——同一件事造了两个词 | 新造的词最容易出错 |
| **17** | **"拆解不是分解指标，是分配配额"** | 把**知识决定的自由度**当成了**架构该做的选择** |
| **18** | **张罗"冲突机制""优先级规则""冲突玛丽"** | 给一个没拆好的拆解打补丁。**正确的答案是"该合并"** |
| **19** | **编了"充电和维保共用排队"** | 回去看数据，它们是两套设施。**为了给自造的机制找例子** |
| **20** | **"车队级策略必须分批才能验证"** | 自我推翻：分批只是"造对照"的手段，而对照是为因果服务的 |
| **21** | **把"机器里的机制"读成"人类的措辞"** | **总纲性的一条**，下面 22–26 全是它的表现 |
| **22** | **造了"多解读"这个场景**（一条经验挂多条知识）| **它不存在**：依据是执行时确定的事实，因果方向是死的 |
| **23** | **提出"逐步状态转移链"**（S₀→决策1→S₁→…）| 它假设了 S₁ 就是 a₁ 的结果。现实里效果**延迟**、**叠加**、还有**外部事件**插进来 |
| **24** | 用"**混合样本 / 重叠**"描述干扰 | 应说「**缺输入**」——前者只能含糊说"有干扰"，后者能指出**缺哪个量** |
| **25** | **"归类"删了又端回来**（问"归类用什么算法"）| 它的残留：知识的**输入量本身就是筛选条件**，没有"归类"这一步 |
| **26** | 把知识分成**拆解 / 方法 / 估算**三类 | 都是 `输入量 → 输出量`。**分类越复杂，维护越麻烦、实现坑越多** |
| **27** | **把"世界"当成"另一个现实"** | 它是**可见性标记**（同一套库，标可见给谁）|
| **28** | **给"缺口"设计"接受"状态** | 工程上"没人看的报警太多了"，该报就报 |
| **29** | **把 HOH 当成"一个统一的设计"** | 它是**三代并存**且互相矛盾。我早先的摘要把三代混着引用，才生出那么多"矛盾" |
| **30** | 说 HOH"**设计从未被验证过**" | **酒馆代有量化表**（5 样本 × 3 模型，含延迟 7.4/17.7/45 秒 + v1→v2 对照）。准确说法是：**只有抽取质量被量化验证过** |
| **31** | 说"**错误码体系永久缺失**" | **错**。`07:204-231` 有完整 23 个错误码 + 18 项配置参数 |
| **32** | 借鉴清单里写"**执行事件的四态**来自 HOH" | **HOH 全库没有那四态**。那是 marie 自己的东西 |
| **33** | **说"知识要单立一类节点"** | **不用**。方法 = `g`，知识 = `f`（见 [09](09-知识图谱与原文片段.md)）。我说这话的理由是"HOH 装不下参数"——而**参数的正本在原文**，这一点我说反了 |
| **34** | 说"**知识节点同时装原文值 + 实测值**" | **不存在**。实测**永远不进知识**；差值是对账现算的、不存 |
| **35** | 提出**玛丽可以"带偏差决策"** | **不做**。它的前提是"实测能成为知识"，**前提就是错的**；而且那会让机器跑在规程前面 |

## 六、待定：图结构的两个选择

> **这两条是纯粹的实现口味，不影响上层结论。** 先记细，落地时再定。

### 选择一 · 关系怎么命名

| | **(A) 单一类型 + 属性** | **(B) 具体类型名** |
|---|---|---|
| 长什么样 | `(发生)-[:LINK {关系:"代入"}]->(量)` | `(发生)-[:代入]->(量)` |
| 好处 | 类型只有一种；"沿任意关系走一跳"是一句 | 一眼看懂语义 |
| 代价 | 图语句读不出语义 | 类型名散在代码里 |

**倾向 (B)**：我们只有九条关系，而且**都有自然的名字**
（输入 / 输出 / 代入 / 依据 / 选了 / 预期 / 属于 / 取代 / 来源），
"用编号统一"的理由在九条上不成立。

#### ⚠️ 但真正要先定的是「关系一共要哪几条」

**换框架之后，清单变了。旧框架的关系大部分对不上了：**

| 旧框架的关系 | 新框架下的处置 |
|---|---|
| `13 导致` | **大概可删**——归因不重要 |
| `11 参与` | **被「代入」取代** |
| `12 发生` | 时间已经是节点的属性 → **可能不需要** |
| `14 先于` | **待定**：时间顺序还要不要显式表达 |
| `1 实例` / `2 是` / `3 属于` | **待定**：词汇之间的层级，**从没讨论过** |
| **新增**：输入 / 输出 / 代入 / 依据 / 选了 / 预期 / 取代 / 来源 | 新框架需要 |

**所以选择一的实质不是"怎么命名"，是"关系清单该定成哪几条"。**

### 选择二 · 数值挂边上，还是挂节点上

| | **(A) 挂边上** | **(B) 挂节点上** |
|---|---|---|
| 长什么样 | `(发生#4711) ──代入{值:4.2}──→ (量:路程)`<br>`(发生#4711) ──代入{值:90} ──→ (量:载重)` | `(发生#4711) {路程:4.2, 载重:90, 天气:雨}` |
| 好处 | 图原生；**"这个量上发生过什么"是一次遍历**；一次发生有多少个量都自然 | 节点少 |
| 代价 | 边数多 | **那就不再是图了**——变成"一行宽表"；查"路程这个量"要扫全表 |

**倾向 (A) 挂边上**：边多是**数据量**问题，不是**结构**问题。

**背景**：值**不做节点**（会造成伪共享），但**做属性没问题**——所以问题只剩挂哪儿。
