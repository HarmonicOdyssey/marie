# 03 · 咬合：知识与经验怎么接起来

> 由[必然结论一](00-为什么.md)推出两样东西，这篇讲**它们之间那一处**。
> 这一处如果设计错了，整个系统就退化成"一个流水账 + 一堆空谈"。

---

## 一、接缝是「量」

**知识声明它要哪些量；经验记录那些量的值。**

```
知识：耗电 = f(路程, 载重, 天气, 车况)
      ↑ 它声明的输入量：路程、载重、天气、车况；输出量：耗电

经验：（发生#4711）{路程: 4.2, 载重: 90, 天气: 雨, 车况: 3年, 耗电: 7}
```

**接缝就是这批"量"。** 知识要哪几个，经验给了哪几个的值——**对得上就能对账，对不上就报缺输入。**

**这是整个设计里唯一的接缝。** 它比"决策"更基础：**对账根本不需要决策**（见第四节）。

---

## 二、对账的单位：一次「发生」

```
一次发生 = 一组同期的（量, 值）
```

**判据很简单**：

```
知识的每一个输入量 + 输出量，都在这一次发生里被观测到了？
   是 → 能对账
   否 → 这一次发生对这条知识**不构成证据**
        → 报「**缺输入**」，并且指出缺的是哪个量
```

> ### 注意这里不是"混合样本"，是「**缺输入**」。
> 区别很大：**"混合"只能含糊地说"有干扰"；"缺输入"能直接指出缺哪个量。**
> 而缺的那个量，正是要去补的东西。

---

## 三、程序**不解读，它重算**

一个真实的例子（矿山调度）：

```
知识说：一圈耗电 5%
A 车还有 11% 的电 → 算法算"再跑一圈再去充更好" → 决策1：继续跑

结果路上出了故障，两辆车卡住 → 基于这个情况做了决策2
处理故障导致堵车，其他车绕路 → **A 车一圈下来耗了 7%**
```

**人类怎么读**：出现意外，路程变长了 → **不是估算算法的问题**。

**程序怎么读——它不解读，它重算**：

```
本次的【实测输入】：
   路程 = 4.2 km    ← 绕路了（本来 3.5）
   载重 = 90 t
   天气 = 雨
   车况 = 3 年

用实测输入重算预期：f(4.2, 90, 雨, 3年) = **5.8%**
实际耗电：**7%**
残差：**1.2%**        ← 这才是耗电算法真正的误差
```

**注意差别**：不是 `5% vs 7%`（差 2%），而是 `5.8% vs 7%`（差 1.2%）。

> ### **"意外"的影响，通过"输入变了"自动进入。程序不需要理解意外。**

---

## 四、延迟、叠加、外部事件——**全都自动消解**

一开始我以为这里需要一套"多决策的链路模型"：

```
S₀ ──决策1(a₁)──→ S₁ ──决策2(a₂)──→ S₂ ……        ← ❌ 这个模型太干净了
```

**它错在假设了 S₁ 就是 a₁ 的结果。** 现实是：

| 现实 | 那个模型假设的 |
|---|---|
| 决策1 的效果要**过几步**才显现 | 下一步就是结果 |
| 那个结果**同时受决策2、决策3影响** | 只受前一步影响 |
| **外部事件（故障）会插进来** | 没有外部事件 |

**而在"重算"框架下，这三条都不需要特殊处理：**

| 问题 | 怎么消解的 |
|---|---|
| **效果延迟** | 对账发生在"**输出被观测到**"的时候，**不需要观察期** |
| **多决策叠加** | 决策2、3 如果改变了**某个输入量**，那个量就被记录了 → 对账用**实测值** |
| **外部事件** | 同上，它改变的是输入 |

> **所以真正要攻的不是"厘清"，是"把输入记全"。**

**而这带来一条硬结论**：

```
不知道"这条路多长"  →  耗电算法永远无法被检验
                    →  而你会以为它错了，去改一个本来正确的算法
```

**"记全条件"不只是提高质量，它是"能不能检验"的分水岭。**

---

## 五、那「依据」是干什么的

**对账不用"依据"，但"依据"另有用处。**

```
（决策#4712）{时刻, 预期结果: {总脱产: 40}}
    ──依据──→ （知识:调度算法@v2）
    ──选了──→ （动作:充电顺序A）
```

| | 干什么 |
|---|---|
| **对账知识** | 用**实测输入 + 实测输出**算残差。**不需要依据** |
| **依据** | **审计与复盘**："当时为什么这么选"、"这次该不该用这条知识" |

**两者都必要，但用途不同。** 别把它们混成一件——**这正是我上一版绕进去的地方。**

**为什么要记"预期结果"**：决策当时算法算出来的那个值，是事后判断"这次决策对不对"的锚。
实际总脱产 52 vs 预期 40 → 差 12 分钟。**这也是"预期 vs 实际"，同一种形状。**

---

## 六、经验 ⊇ 实践

```
经验 = 全部记录（包括没有任何决策的纯观测）
实践 = 有决策的那些
```

**纯观测不构成实践，但它们不是废料**——**它们是知识最主要的证据来源**（比如耗电估算，跑一圈就产生一个样本，不需要任何决策）。

---

## 七、知识与经验是**多对多**

| 方向 | 例 |
|---|---|
| **一条知识 ← 多条经验** | 耗电估算，跑几圈就有几个样本 |
| **一次经验 → 多条知识** | 一次调度决策同时用到：路段油耗、点保维周期、充电耗时 |

**一次复杂的发生，可能需要多条知识联合才能解释** —— 这一点直接决定了"解释率"怎么算（见 [05](05-建模玛丽.md)）。

**而且多对多是"一次发生同时给多条知识提供证据"**，不是"一个结果被多条知识解读"：
**后者不存在**——依据是执行时确定的事实，因果方向（先依据、后结果）是死的。

---

## 八、本篇的结论

| # | 结论 |
|---|---|
| **1** | 接缝是**量**：知识声明它要哪些量，经验给那些量的值 |
| **2** | 对账的单位是**一次发生**（一组同期的量、值） |
| **3** | 缺量 → 报「**缺输入**」并指出缺哪个，**不是**"混合样本" |
| **4** | **程序不解读，它重算**——用实测输入算预期，与实测输出比 |
| **5** | 延迟、叠加、外部事件**全都自动消解** |
| **6** | **依据**用于审计复盘，**与对账是两回事** |
| **7** | 记全输入是**能不能检验的分水岭** |
