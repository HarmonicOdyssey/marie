# 07 · 写入纪律与归一化

> **实现层。** 两件事：经验怎么保证"只加"，以及"多个说法算不算同一个东西"。

---

# 第一部分 · 写入纪律

## 一、经验只加

| 允许 | 不允许 |
|---|---|
| 新增一条记录 | 修改任何已有记录 |
| 追加一条"更正"记录 | 删除任何记录 |

**为什么是红线**：经验是**唯一不可重建**的东西。原文丢了可以重抓，知识错了可以重编，**只有"当时究竟发生了什么"丢了就永远丢了。**

## 二、单一写入入口

**全系统只有一个函数能写经验，而且它只做新增。**

它同时负责：

| 校验 | 不通过就 |
|---|---|
| 类别在固定枚举内 | 拒绝 |
| 时间格式定宽 | 拒绝 |
| **分配单调序号** | 同上 |
| 因果父指针若不为空，必须指向已存在的记录 | 拒绝 |
| **不许写半条** | 回滚整个事务 |

**检查方式**：全代码库检索"对经验层的写操作"，**必须只出现在那一个模块里**。**这条用脚本查，不靠自觉。**

## 三、独立审计

**如果数据库不能"阻止"修改，那就必须"能发现"修改。**

| 检查 | 怎么做 | 能发现什么 |
|---|---|---|
| **内容指纹** | 每条经验记录带写入时的**内容哈希**；审计重算并比对 | **被就地改过** |
| **序号单调** | 扫全部序号，必须严格递增无重复 | 序号被弄乱、被回填 |
| **依据完整** | 每条"依据"边指向的知识版本必须存在 | 引用了不存在的版本 |

**两条纪律**（用来报告"经验是否被篡改"的机制，不能依赖经验本身）：

1. **审计必须能独立跑**；
2. **审计的结果不落在被审计的那部分库里**。

## 四、知识不是只加，但**改就是追加版本**

```
(知识:错峰充电@v1) {文件: …/v1.py}
(知识:错峰充电@v2) {文件: …/v2.py}
(知识:错峰充电@v3) {文件: …/v3.py}

@v3 ──取代──→ @v2 ──取代──→ @v1
```

**版本 = 另一份函数文件 + 另一个节点。它就是数据存储。**

**引用永远是 `key@版本`，不是"当前最新"。**
因为未比对完的决策，要按**它当时依据的那一版**去对账。

**"当前是哪一版"是一个投影**——没有"取代"边指向它的那个就是当前，不另存字段。

### 一条边界：这些不在玛丽的范围里

| 不在范围 | 归谁 |
|---|---|
| diff、分支、回滚 | 业务落地时按具体场景定 |
| 审查流程（谁能改、怎么批） | 同上 |
| 函数文件本身怎么写、用什么语言 | 同上 |

**玛丽只需要知道两件事**：这一版**指向哪个文件**，以及它**取代了哪一版**。

# 第二部分 · 归一化

## 五、归一化在做什么

制度手册写"前置防撞包"，另一份写"测距雷达"，第三份写"前置雷达"——**它们可能是同一个东西**。

不认成同一个，后果是：概念碎片化、证据被分散、检索找不到。

## 六、两道闸（**编辑距离已废除**）

| 闸 | 判定 |
|---|---|
| **① 精确匹配** | 同类型 + 名称完全相同 → 直接合并。**主路径** |
| **② 语义相近** | 名称的向量相似度过阈值 → 合并为候选 |

**为什么废除编辑距离**：它只为抓**纯拼写变体**这一个很窄的案例（`UserServcie` vs `UserService`），
却要付**"误并"的风险**——而合并是**破坏性的**：错并一次，两条知识永久粘在一起。

**如实记一个已知缺口**：短字符串与型号（`DB-01` / `DB-02`）的语义向量区分力弱。
**这条由下面的作用域边界兜** —— 它们根本不允许被归一。

## 七、作用域边界（本篇最要紧的一节）

**归一化会主动制造错误**：它会努力把 `DB-01` 和 `DB-02` 认成同一个东西——因为它们的向量确实很像。**而那是灾难。**

所以真正要设计的是**边界**：

| 东西 | 例 | 是不是节点 | 归不归 |
|---|---|---|---|
| **词汇名**（对象、量、动作）| 前置防撞包 / 测距雷达、服务器 | 节点 | **归** ← 归一的价值在这里 |
| **标识符**（型号、版本、编号）| `DB-01`、`V1.5`、`#4711` | 节点 | **绝不归** |
| **数值 / 属性值** | `2米`、`85%`、`+0.18` | **不是节点**（是属性或文本）| **不适用** |
| **时间 / 位置** | 2026-03-05、北京 | 节点 | **不靠相似度**，抽取时直接写成规范形式 |

### 三条边界为什么成立

**① "数值不是节点"，问题自己消解。**
只要数值不作为节点，"要不要归一 `2米` 和 `2 米`"这个问题**根本不存在**。

**② "标识符绝不归"是防灾难的那一道。**
`DB-01` 和 `DB-02` 是**两台不同的设备**。归错了，两台设备的历史混在一起——**而且不可逆**。

**判定"这是标识符"——两道，取并集**（宁可漏归，不可错归）：

```
· 形态规则：含数字、或形如编码（V1.5、#4711、DB-01）→ 跳过归一
· 抽取阶段打标：由模型判断"这是不是一个具体的型号/编号"
```

**③ "时间/地点不靠相似度"**，由抽取阶段**直接写成规范形式**。
让相似度去判断"今年元旦"和"2026-01-01"是不是同一个，是把一件确定的事交给一件概率的事。

## 八、归一只作用于知识层

**归一作用于词汇节点**（对象、量、动作的名字）——这就是它存在的意义：概括。

**但标识类词汇除外**：`DB-01` 是一个对象，却**不参与归一**。
因为它**本身就是个体**，它靠关系连到自己的历史——**而那正是归一会破坏的东西**。

## 九、顺序不能颠倒

```
① 抽取 → 候选概念
② **先排除**：标识符（形态规则 ∪ 模型标记）
③ 排除：时间/地点 → 走"直接规范化"
④ 精确匹配 → 命中即合并
⑤ 语义相近 → 过阈值即合并
⑥ 合并 → 计数累加；世界分别加
```

**为什么必须先排除再归一**：先归一再去排除的话，**被错并的节点已经粘在一起了**，排除来不及。

## 十、待实测（不能拍）

| 事项 | 说明 |
|---|---|
| **语义阈值** | 具体取多少，**必须用真实词汇表校准**，而且应当**可配置** |
| **嵌入模型与维度** | 维度写错会**静默失效**（算出一个荒谬的相似度而不报错）|
| **形态规则的具体式样** | 需要一份可维护、可扩充的清单 |
