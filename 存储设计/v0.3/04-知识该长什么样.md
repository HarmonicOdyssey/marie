# 04 · 知识该长什么样

> 由[必然结论二](00-为什么.md)推出：**知识必须是可被推翻的形状。**
> 而[咬合](03-咬合.md)给出了它的形态：**输入量 → 输出量**。

---

## 一、**一种表达**：输入量 → 输出量

```
知识 = 一个函数：输入量 → 输出量
      + 参数
```

**不分拆解 / 方法 / 估算——它们都是这个形状。**

| 算什么 | 输入量 | 输出量 |
|---|---|---|
| 一圈耗多少电 | 路程、载重、天气、车况 | 耗电 |
| 充一次要多久 | 起始电量、桩功率、电压、温度 | 充电时长 |
| 有几次机会拐去充电桩 | 各车位置、任务状态 | 机会数 |
| **目标 A 摊成子指标** | B1、B2…… | A |
| **充电顺序怎么定** | 各车状态 | **它预期的结果**（如"总脱产 40 min"）+ 它选出的顺序 |

**分得越复杂，维护越麻烦、实现坑越多。所以：一种结构，最多加一两个属性。**

### 唯一一个属性：「用来分工」

有一类知识的**输入量是要派给下游玛丽的**（"把目标 A 表达成 B1、B2"就是这一类）。

**这类知识的输入量，就是 marie 说的「子指标」。** 两词是一回事，别当成两样：

```
子指标  =  被派给下游的那个量  =  这类知识的一个输入量
```

它多一条要求（见第三节判据 4）——**因为派出去的每一个量，都要有人能对它动手。**

**其余知识（估算法）没有这条要求**：天气没有手段，但它是耗电算法的正当输入。

---

## 二、唯一的标准：**可被推翻**

> **一条知识写得好不好，看它多容易被推翻。**
> 如果一条知识"怎么都对"——比如"看情况处理"——那**它不是知识**。

**为什么这条是硬的**：一套系统如果允许无法被推翻的东西进入知识库，它们会迅速填满它——**因为它们永远正确、永远不需要修改、永远不产生缺口**。此后系统所有判断都建立在它们之上，**而它们什么都没说**。

**落到操作上**：**每一条知识的每个输入量与输出量，都必须能在某个具体的（对象、时刻）上被观测到。**

---

## 三、输入量的四条要求

| # | 要求 | 不满足的后果 |
|---|---|---|
| **1** | 每个输入量**可观测** | **永远无法对账**——而你会以为算法错了，去改一个本来正确的算法 |
| **2** | 输入量之间**不冗余**（各占一个自由度）| 一个自由度写成两个，白算 |
| **3** | 残差**没有结构** | 漏了东西 |
| **4** | （**仅对"用来分工"的知识**）每个输入量**有手段** | 派出去也没人能对它动手 |

> **判据 4 推出一条区分：「量」≠「玛丽」。**
> **量是坐标**（谁都能用）；**玛丽是"有人能对它有手段"**。
> 一个量没有手段，它仍然可以是别的知识的正当输入量（天气就是），
> **但它不该被派给一个玛丽**——否则那个玛丽会每班报一次"我改变不了它"。

### 判据 3 的两个看法，第二个更有用

| 看什么 | 怎么算 | 说明什么 |
|---|---|---|
| **① 残差的量级** | 与输出量自身的波动比 | 残差 << 波动 → 算法不错 |
| **② 残差有没有结构** | 残差与"未纳入的量"的相关 | **有相关 → 漏了那一项** |

**②比①有用得多**：①的"多小算小"要一个拍出来的基准；②**不需要基准，它直接给出"漏了谁"**。

```
例：耗电估算的残差与「天气」相关 −0.52
    → 而天气没在输入里 → **漏了天气**
```

### 一个很阴的陷阱：**残差小 ≠ 算法合理**

```
把"今天的圈数"估成"昨天的圈数" → 拟合极好（自相关）
但"昨天的圈数"：已经发生、影响不了、派不出去
→ 判据 4 直接把它拦掉（若它是"用来分工"的知识）
```

**统计上漂亮、语义上荒谬的算法是常见的。**

### 机器查不了的那一条

> **"这到底是不是真正的输入"——必须人下。**

**数据只能给关联强度，给不了"构成"。** 这是唯一不能机械化的一条，也正是"只报警不判决"的根源（见 [05](05-建模玛丽.md)）。

---

## 四、冗余（自由度）——判据 2 展开

> **两个输入量，一个变了、另一个就被完全决定 ⟹ 它们是一个自由度的两种写法。**

**例子**：车去加油 → 跑运输的时间一定减少。

```
加油时间 ↑ 1 分钟  ⟹  运输时间 ↓ 1 分钟（总时间固定）
```

**这不是"两个量互相影响"，这是"一个自由度被写成了两个"。**

**处置**：只留一个，或者把它们放到**不同的层**（`A ← 可用时间 ← 总时间 − 加油时间`，那是链，不是并列）。

### 加法是合法的，冗余才不合法

```
A = (480 − B1 − B2) ÷ C    ← B1、B2 各占一个自由度 → ✅ 不冗余
B2 = 480 − B1              ← 一个自由度写成两个     → ❌ 冗余
```

**区别在"能不能各自单独取不同的值"，不在"是不是相加"。**

### 怎么查

```
① 特例：B1 + B2 是不是常数？  → 算 (B1 + B2) 的方差 ≈ 0
② 一般：分箱 B1，看箱内 B2 的方差  → Var(B2 | B1) ≈ 0 即冗余
```

**三条限制（如实说）**：样本要够；只能测线性/单调关系；**只能发现数据上表现出的冗余**。

---

## 五、残差是**唯一的**对账方式

**没有第二套机制。一种知识、一种对账：**

```
残差 = 实测输出 − 函数(实测输入)
```

**这就是为什么[延迟、叠加、外部事件都不需要特殊处理](03-咬合.md)**——
它们改变的是**输入**，而输入是实测值。

### 残差指向两种不同的修改

```
残差的量级大、但没有结构   →  多半是参数不准   →  **改参数**（拟合）
残差有结构（与某个量相关） →  输入量选得不对 →  **改结构**（增删输入量）
```

**这两件事的区别很要紧**：改参数是**机器能做的**（拟合）；改结构**必须人来**（见 [05](05-建模玛丽.md)）。

### 但残差要能说明问题，**样本得够**

```
跑过两次 → 那不叫规律，那叫两次
```

**"重复够多"是[必然结论三](00-为什么.md)的直接要求**：我们靠**重复稳定**认规律，
所以**样本量是证据的一等属性**，必须随结论一起给出。

---

## 六、什么时候**不做对账**：缺输入

```
知识的输入量或输出量，有一个没在这次发生里被观测到
  → 这次发生对这条知识【不构成证据】
  → 报「缺输入」，并指出缺的是哪个量
```

> **注意这里不是"混合样本"，是「缺输入」。**
> **"混合"只能含糊地说"有干扰"；"缺输入"能直接指出缺哪个量**——而那个量正是要去补的。

**而"缺输入率"本身是一个要上报的信号**：它高，说明**观测没覆盖到算法需要的量**。

---

## 七、限制与红线

**限制不是量，限制是"对某个量的一个条件"。**

| | 是什么 | 例 |
|---|---|---|
| **量** | 一个**可观测**的东西 | 脱产时间 |
| **限制** | 对它的一个**条件** | 脱产时间 ≤ 82 min |

**它是知识的内容**（函数的关系里可以含条件）。**不需要单独的"限制"概念。**
（"剩余额度"是投影——`预算 − 实际`，不存。）

**红线 = 硬度很高的限制。** 所以知识里的条件需要**一个属性**：

```
破了怎么办？  →  上报（硬，系统停在那儿等人） / 只是记账（软）
```

**不需要单独的机制，只需要这一个属性。**

### 两处容易算错的地方（从真实场景看出来的）

**① 红线要用「下尾」看，不能用均值。**

```
最低电量：均值 31.4%（看着很安全）／最小 11.4%（破线）
```

**均值完全掩盖了破线。** 目标看均值/中位，**红线看下尾**——这是两类量在统计上的根本不同。

**② 防患型动作要用「不良事件率」衡量，不能用「涨幅」。**

充电**不提升**任何正向指标——它**避免更坏的情况**（半路没电）。
用"涨了多少"去衡量它，会得出"**充电有害**"（充一次就少跑半个班）。
**对这类知识，对账的落点是"坏事件的发生率有没有降"，而不是"好指标有没有升"。**

---

## 八、什么**不**进知识

| 不进 | 例 | 为什么 |
|---|---|---|
| **落不到具体对象与时刻上的话** | "看情况处理"、"注意安全" | 无法被核对 → 无法被推翻 → 不是知识 |
| **具体的值** | 电量 = 22% | 值相同≠同一 → 属性，不做节点 |
| **派生量** | 排队 40 分钟 | 算得出来 → 不存 |
| **因果断言** | "A 导致了 B" | 归因不重要；而且数据给不了 |

**而"看情况"有容身之处**：

> **它不进知识，但可以进「缺口」。**
> 缺口记的是：**"我们知道这里该看情况，但说不清要看清什么。"**
>
> **它不是废话——它标记了知识地图上的空白。**

---

## 九、本篇的结论

| # | 结论 |
|---|---|
| **1** | **一种表达：输入量 → 输出量。** 不分拆解/方法/估算 |
| **2** | 唯一属性：**「用来分工」**（它的输入量要派给下游 → 多一条"有手段"要求）|
| **3** | 输入量四条：可观测 / 不冗余 / 残差无结构 /（分工类）有手段 |
| **4** | **残差小 ≠ 合理**；"残差有没有结构"比"残差大不大"有用 |
| **5** | **残差是唯一的对账方式**——延迟/叠加/外部事件全因此自动消解 |
| **6** | 缺量 → 报「**缺输入**」，且指出缺哪个 |
| **7** | 限制是知识内容；红线只是"破了要上报"的条件 |
| **8** | 落不到实处的不是知识，但进缺口 |
