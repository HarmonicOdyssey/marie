# 08 · 组装与缺口

> **实现层最后一篇。** 组装回答"一个目标怎么摊成一张组件图"；
> 缺口回答"走不下去的地方怎么报上去"。

---

## 一、组装：把目标摊成一张组件图

```
① 盘点与复用优先（**顺序不可颠倒**）
     池子里有没有能产出这个指标的玛丽？
       有  → 复用，再往下展开它的输入指标
       没有，但这个指标可以直接观测 → 它是一个叶子
       两者都不成立 → **缺口，记录位置**
② 逆向拆解
     用那条知识把指标摊到它的输入量上，逐个递归
③ 产出两样
     · 本次运行需要的组件图
     · 缺口清单（带位置）
```

**"复用优先"的顺序不能颠倒**——先问池子，再判可观测，最后才报缺口。
颠倒的后果是**把本来能复用组件的地方报成缺口**，而缺口会让人去做一件根本不需要做的事。

## 二、三种形态不引入新概念

| 形态 | 什么时候 | 怎么表达 |
|---|---|---|
| **树** | 单目标、无共享 | 组件图 |
| **森林** | 多目标、**共享**原子组件 | 同一个图上多个根 + 标出共享的组件 |
| **图** | 指标互相影响、有环 | 同一个图 + 环上的边标为**时间延迟** |

**判定标准是"共享"，不是"目标数量"。** 一个目标也是树；三个目标但互不相干，仍是三棵树。

**有环怎么办（时间延迟）**：A 影响 B、B 又影响 A → 不合并、不丢弃，而是标成时间延迟（读上一步的 A）。
**这里有个真实的坑**：如果"节点已存在就复用"的判断排在环检测**之前**，环会被**静默当成共享节点**——图会以"已展开"的样子交出去，而"读上一步"这条规则永远不生效。**不报错，只给出一张看起来正常的错图。**

## 三、同一指标有多个玛丽怎么办

```
① 使用方有偏好 → 按偏好
② 没有偏好     → 比**经验**（各自依赖的方法有多少证据撑着、条件覆盖如何）
③ 都不可比     → **上报为缺口，请人指定**——不猜
```

**注意第 ② 条**：**玛丽的选择本身也要靠经验**，而不是靠名字。这是[知识与经验咬合](03-咬合.md)的一个消费点。

## 四、缺口：五类，都带位置

| 类型 | 什么时候报 | 例 |
|---|---|---|
| **数据缺口** | 指标既不可观测、也无法再分解 | "路过人数"没有数据源 |
| **知识缺口** | 有目标，但没有能把它摊成子量的知识 | 不知道该把它摊成什么 |
| **方法缺口** | 有拆分，但没有任何可用方法 | 知道要影响"阻塞数"，但不知道怎么做 |
| **组件缺口** | 池子里没有能产出该指标的玛丽 | 该指标没人负责 |
| **结构缺口** | 知识的形状有毛病（**输入量四条要求**任一不满足）| 见 [04](04-知识该长什么样.md) |

**而"落不到网格上的话"也归到这里**：
"我们知道这里该看情况，但说不清要看清什么"——**它标记了知识地图上的空白。**

## 五、两条纪律

**① 缺口写成"在这个指标的这一步做不了"，不是"这个目标做不了"。**

```
❌  无法完成目标「提升当班圈数」
✅  组装：指标=排队时长，这一步缺方法
```

前者无法行动，后者**直接指出该补什么**。

**② 缺口是报警，不是资产。**

- 补上之后**重跑目标**即可——缺口自然不再出现。**重跑就是验证，不需要反查表。**
- **有些缺口永远补不上。那也没关系**——该报就报，没人看，出了事自然有人负责。
- 保留的价值是**统计信号**：这个月缺口集中在哪些指标。

**这与["只报警不判决"](05-建模玛丽.md)是同一条纪律**：系统负责指出位置，人决定处置。

## 六、报告分层

| 层 | 收什么 | 推不推 |
|---|---|---|
| **入账** | 全部事实 | 不推（就是经验）|
| **报告** | 全部执行结果与误差，分 立即 / 尽快 / **备查** | 立即、尽快推；**备查只入账、只进列表** |
| **上报** | **只含三类：缺口 / 预测失准 / 异常** | 推 |

**"备查"必须真的不推。** 一个真实的教训：如果"推不推"是一个**独立参数**而不是由级别决定，那么"备查"级别的结果照样会被推——**"正常运转时推送显著减少"这条就永远不成立**。

**报告的目的是"请人做一件只有人能做的事"，不是传递一个数字。**

## 七、运行循环（简）

每个节拍：

```
① 读知识   该拆成什么、有哪些方法、预期是什么、各自有多少证据
② 对账     当前值与目标比 → 在容差带内？超差？
③ 选方法   超差 → 按经验与适用条件选一个
④ 生成预测 冻结预期与条件                              ← 写经验
⑤ 执行     派发（执行体：人 / 机器 / 外部接口）          ← 写经验
⑥ 收观测   观测回流 → 与冻结的预期对账                  ← 写经验
⑦ 记账     全部入账；按报告分层决定推不推
```

**四条纪律**：

| 纪律 | 说明 |
|---|---|
| **不因目标达成而停止** | 达成之后继续观测、继续记账。系统**不结项** |
| **正常运转时不推送** | 进入容差带后账目照常累积，但不主动推 |
| **执行体不产生分叉** | 人 / 机器 / 外部接口走**同一条**通路，差别只在记录里 |
| **归因后置** | 只记"效果如何"，不判"为什么" |

**心跳巡视**（独立于业务事件的定时器）只问两件事：**预测到期未观测**、**数据源静默**。
**它的价值在于**：没有它，系统只能对"发生的事"作反应——数据源断了三天，账面会显示"指标平稳"，**而那不是平稳，是瞎了**。
**心跳没产出报告就不留痕**，但"该发生的事没发生"是事实，**发现它的结论要入账**。
