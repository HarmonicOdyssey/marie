# 附录B · 术语表

> 原则：**用自解释的词，不用过几天就忘的词。**
> 最后两节（**易混淆对照**、**已废除的词**）比正表更常用到。

---

## 一、两样东西

| 术语 | 定义 |
|---|---|
| **知识** | **程序里用来计算的算法与参数**。形状是 `输入量 → 输出量`。**不是人类写的规则条文** |
| **经验** | **实践过程中收集到的实测数据**。只加，不能改。**不是人的经历** |
| **一次发生** | 经验的基本单位：**一组同期的（量, 值）** |
| **实践** | **有决策的那些发生**（经验 ⊇ 实践）|

## 二、知识与经验的接缝

| 术语 | 定义 |
|---|---|
| **量** | 可观测的东西（路程、耗电、电量）。**知识与经验共用的坐标** |
| **输入量** | 知识声明的、它要用的量 |
| **输出量** | 知识算出来的那个量 |
| **代入** | 一次发生里，"这个量当时是多少"（值挂在边上）|
| **残差** | `实测输出 − 函数(实测输入)`。**知识唯一的对账方式** |
| **缺输入** | 知识要的某个量，这次发生里没观测到 → **这次不构成证据**（并指出缺哪个）|
| **依据** | 这次决策用了哪条知识。**用于审计复盘，不用于对账** |

## 三、循环里的东西

| 术语 | 定义 |
|---|---|
| **决策** | **一次动作的选择**。带"依据 / 选了 / 预期结果" |
| **预期结果** | 决策当时算出来的值（"这样排预计总脱产 40 min"）。**事后判断这次决策的锚** |
| **限制** | **对某个量的一个条件**（不是量本身）|
| **红线** | **硬度很高的限制**：破了要**上报** |
| **破了怎么办** | 知识里的一个属性：上报（硬）/ 只是记账（软）|

## 四、图上与实现

| 术语 | 定义 |
|---|---|
| **词汇** | 量与对象、动作、时间、位置——**知识与经验共用的那批量** |
| **世界** | 数据上的一处**可见性标记**：权限 / 用户 / 场景复用。**不是"另一个现实"** |
| **取代** | 版本链上的边 |
| **当前版本** | **没有"取代"边指向它**的那个。不另存字段 |
| **单调序号** | 发生记录**顺序的唯一依据**。**不是时间戳** |

## 五、检验与反省

| 术语 | 定义 |
|---|---|
| **解释率** | 能被解释的**发生**数 ÷ 总数。**建模玛丽的输出指标** |
| **被解释** | 两件事同时成立：**量齐**（知识要的输入输出量都观测到了）＋**残差可接受** |
| **建模玛丽** | **"从数据里长出知识"这件事本身**，它就是一个玛丽 |
| **报警** | 系统只把**位置 + 事实 + 线索**指出来 |
| **判决** | 系统**自己改知识**。**不做** |
| **缺口** | 走不下去的地方。**必须带位置** |
| **自由度** | 一个能独立取值的维度 |
| **冗余** | 一个自由度被写成了两个输入量 |

## 六、易混淆对照（**最容易出错的地方**）

| A | B | 差别 |
|---|---|---|
| **经验** | **知识** | 实测数据 vs 算法与参数。**只加 vs 可改** |
| **发生** | **决策** | 发生是一组（量,值）；决策是发生里带"选了什么"的那种 |
| **输入量** | **依据** | 输入量用于**对账**；依据用于**审计**。**别混** |
| **世界** | **对象** | 可见性标记 vs 现实里的某个东西 |
| **独立** | **加法** | 独立 = **不冗余**；**加法本身没问题** |
| **报警** | **判决** | 指出位置 vs 自己改知识 |
| **缺口** | **空结果** | "答不了，缺什么在这儿" vs "没有"。**只有前者带地址** |
| **缺输入** | **算法错** | 量没观测到 vs 算得不准。**混了就会去改一个本来正确的算法** |
| **残差大** | **残差有结构** | 大只是不准；**有结构说明漏了某一项** |

## 七、已废除的词（不要再用）

| 废弃 | 处置 | 为什么 |
|---|---|---|
| **账本** | **经验** | "账本"太不通用了 |
| **主体**（作为一个维度）| **对象就是词汇节点** | 它是"造对照"的产物，而"归因不重要"否掉了那个需求 |
| **归类** | （整个概念删除）| 知识的**输入量本身就是筛选条件**，不需要"归类"这一步 |
| **认定 / 对齐** | （删除）| 同一件事，我造了两个词，都不必要 |
| **多解读**（一条经验挂多条知识）| （删除）| **场景不存在**：依据是执行时确定的事实，因果方向是死的 |
| **混合样本 / 重叠** | **缺输入** | "混合"只能含糊说"有干扰"；"缺输入"能指出缺哪个量 |
| **情态 / 声明·推演·实测** | （删除）| 知识不能自证可信 |
| **执行偏离** | （删除）| 那是归因，已定不做 |
| **提及表（`mentions`）** | **来源关系** | 溯源是边，不是表 |
| **表层形式 + 出现次数** | （删除）| 归一是语言模型做的，**拿不到这个信息** |
| **抽取作业（`extraction_run`）** | （删除）| 冗余 |
| **缺口反查 / 缺口"接受"** | **该报就报** | 重跑就是验证；工程上没人看的报警太多了 |
| **RQI / 四类动作 / 薄接口契约 / 存储可替换** | **读知识 / 读经验 / 写经验** | 原设计把一句"别到处写 SQL"放大成了架构契约 |
| **对账强度阶梯 / 对照组 / 平行趋势 / 分批上** | **记全条件 + 重复够 + 结果稳** | 归因不重要 |
| **分配额度 / 优先级规则 / 冲突玛丽** | **知识的表达形式**（或"没拆开"的信号）| 架构不该为它们提供机制 |
| **"拆解知识" / "方法知识"** | **知识（一种表达）** | 都是 `输入量 → 输出量`，分类只会增加维护成本 |
| **"三省吾身"玛丽** | **暂缓** | 已明确不保留它的描述，免得以后混乱 |
