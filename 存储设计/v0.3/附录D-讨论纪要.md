## 二、根本框架（这部分是定案的）

### ✅ 1. 只有两样东西要存

| # | 存什么 | 能不能改 |
|---|---|---|
| **1** | **发生了什么事**（含人手动打的标签） | ❌ **只能加，不能改** |
| **2** | **我们相信什么**（含"怎么归类"的规则） | ✅ **能改，旧版本留着** |

**其余的（排队时长、平均圈数、误差、可信度、每条记录属于哪一类）全是现算的，不存。**

### ✅ 2. "归类"不需要单独存——它不是第三样东西

这句话是我这几轮最大的简化。归类有两个来源：

| 归类的来源 | 它其实是什么 | 存哪 |
|---|---|---|
| **按规则算**（"电量落在 20~25% → 归 A 类"） | 规则是**知识**；归类是**算出来的** | ❌ 不存，随时重算 |
| **人手动打标签**（"这次我看是异常"） | 这是**人做了个动作** | ✅ 存进第一样（当事件） |

**好处**：规则一改，所有归类**自动跟着变**——因为归类从来没被存过。

### ✅ 3. 知识与实践**相互依存**，不是两种东西

你的原话：

> 缺少依据和缺少实践经验**都是一种不完全的状态**，长期来说肯定是都有且相互依存的。

→ 所以我原先提的"实验型实践 / 观察型实践"**二分被推翻**（❌）。
→ 正确表述：**"依据"不是记录的属性，而是一条可以随时建立、也可以改挂的关联。**

### ✅ 4. 图上只放**"相同即同一"**的东西

你对"指标的值不能做属性/节点"那条规则的澄清：

> 最初知识图谱+原文片段的方案是**面向 RAG** 的。如果属性值作为节点，比如电量 22 这个数值，"22" 这个概念节点可以指向很多完全不相干的 Fact，**这是完全没有意义的**。所以才有这么个说法。

→ 那条规则**不是铁律**（❌），它的本质是**伪共享**问题。
→ 重新表述成一条准的：

> **实体名相同 → 是同一个东西 → 做节点。**
> **值相同 → 不代表什么 → 做属性，不做节点。**

**而这条原则同时覆盖了"归一"**：

| | 问的是什么 |
|---|---|
| **归一** | "测距雷达"和"前置防撞包"——**名字不同，是不是同一个东西？** |
| **值 vs 节点** | 两条事实都有"22"——**名字相同，是不是同一个东西？** |

**两个问题问的是同一件事。**

### ✅ 5. 用知识图谱，不用 SQL 类数据库

## 三、关于"从数据里长出知识"（发现）

### 🔶 6. 拆解优先沿**恒等式**，不沿相关性

| 用 | 不用 |
|---|---|
| `圈数 = (当班时长 − 脱产时间) ÷ 单圈周期`（会计恒等式） | `圈数与排队时长相关 −0.44`（相关） |

**恒等式不可能错；相关性随时可能是混杂。有恒等式可用时，绝不退到统计。**

### 🔶 7. 知识靠什么"站住"，有三种，可信程度完全不同

| 三种 | 例 | 可信程度 |
|---|---|---|
| **算出来的 / 定义** | 圈数 = 在位时间 ÷ 单圈耗时；少 5 辆车 → 少 7.8% 货 | **最硬**——不会错 |
| **有道理的（机制）** | 排队 = f(到达率)（排队论） | 硬——道理已知，参数实测 |
| **比出来的** | 早充的车跑得更多 | **最软**——可能跑得多的车才早充 |

> **系统必须能分清这三种**，否则会把"比出来的"当成"算出来的"去用。
>
> **"证据有多硬"不是拍出来的，是从"支撑方式"推出来的。**

### 🔶 8. 对账的强度阶梯（越靠上越优先）

| 级 | 靠什么对账 | 需要分批吗 |
|---|---|---|
| **1** | **恒等式**（会计、物理守恒） | ❌ |
| **2** | **已知机制 + 实测参数** | ❌ |
| **3** | **历史自然变异**（不同条件下的对照） | ❌ |
| **4** | **主动实验**（分批、随机） | ✅ **这就是分批** |
| **5** | **前后对比** | ❌（但也最没用） |

**分批是第 4 级，不是必需品。** 我一度说成"车队级策略必须分批"，**已自我推翻**（❌）。
**只有当效果依赖"人的响应"、机制不可算时，分批才真的必要。**

### 🔶 9. "决定什么算同类"**必须由人提供**——这是提炼规律的核心限制

> **提炼规律 = 决定"哪些差异可以忽略"。**
> 而这个决定**不是数据给的**：数据只告诉你差异**存在**，不告诉你差异**可以忽略**。

- **归得太粗** → 把两件不同的事平均成一个数
- **归得太细** → 每组一条样本，无规律可言

**数据能检验这个划分，但不能给出这个划分。**

### 🔶 10. 观测数据的两个险坎（都是"朝有效方向偏"）

| 坎 | 具体样子 | 能否补救 |
|---|---|---|
| **均值回归 + 选择偏差** | 你会**专挑差的车去救**，而差的会自然回升 → 效果被系统性高估 | 靠**对照 + 平行趋势**（趋势不平行则结论作废） |
| **缺失非随机** | 只有**盯得紧的车**才有完整观测，而盯得紧=问题严重 → "完整样本"≠全部门店 | **只能发现**（比较完整/不完整样本在动作前的分布），不能修复 |

### 🔶 11. 能得到 / 得不到（阶梯）

| 层次 | 需要什么 |
|---|---|
| 描述 | 无 |
| 对齐轨迹 | 动作时间 + 观测 |
| 分组差异 | ＋起点状态 |
| **条件性效果** | ＋**对照 ＋ 平行趋势** |
| —— 下面做不到 —— | |
| 因果确证 | 随机化或强识别策略 |
| 从未做过的做法 | 数据里得有 |
| "构成关系" | 人的语义判断 |
| "为什么" | 归因（已定不做） |

### 🔶 12. 知识的边界：**可证伪性**

> **一条知识写得好不好，看它多容易被推翻。**
> 如果一条知识"怎么都对"——比如"看情况处理"——那**它不是知识**。

**这条比"能落到网格上"更准**，也顺手解决了真实 SOP 里"拿捏分寸"那部分：**它们不是知识，因为它们无法被推翻。**

## 四、关于"建模玛丽"

### 🔶 13. "从数据生成玛丽"**本身就是一个玛丽**

```
建模玛丽  B-建模
  输出指标    所产出知识的**残差 / 样本外误差**
  可用方法    ← **就是第 7 条里那三种支撑方式**
     · 把恒等式的分量测准
     · 标定机制参数
     · 找状态相近的记录做配对
  对账        换个方法之后，残差降了吗？（**可测**）
  缺口        残差降不下来 → 上报"这条知识我撑不住"
```

**关键**：它**不需要任何新机制**，用的就是 marie 已有的"拆解 + 选方法 + 对账 + 缺口"。
**所以"维护玛丽"不是系统外的手工活，而是一个可度量的循环。**

### 🔶 14. 它撞到的墙

| 墙 | 处置 |
|---|---|
| **决策理由不可得**（你明确：有决策记录，但没有"为什么"） | **不需要知道"为什么"，只需要知道"他当时看到什么"** |
| **"他当时看到什么"可重建** | **= 所有「入账时间 ≤ 那一刻」的记录** ← 靠第二根时间轴算出来，**不需要新字段** |
| **残余混杂**（调度员凭经验/无线电做判断） | 无法根除，只能**如实标出**："配对前后结论变了多少"是一份必须交出的证据 |

## 五、从无人车 mock 里学到的（场景层）

### ✅ 15. 场景事实（你确认的）

| 项 | 值 |
|---|---|
| 效率 = | **当班圈数**（跑了多少圈） |
| 数据 | 有动作序列；一段历史 + 持续流入 |
| 调度决策 | 有记录，**没有"为什么"** |
| "有序" | 车要按期点保维、没油没电要去加/充；但**桩位与工位有限**、**要专门跑过去**；去多了堵、去勤了亏 |

### 🔶 16. 玛丽这样拆（四个）

```
B-运输（当班圈数）   ← 目标
  ├─ 脱产时间 → B-场站（脱产时间）
  ├─ 单圈周期 → ✂️ 不成玛丽（只做系数）
  ├─ 【红线】最低电量 → B-电量（班内最低电量）
  └─ 【红线】维保不超期 → B-维保（维保超期率）
```

### 🔶 17. 四条拆解判据

| # | 判据 |
|---|---|
| **1** | 拆解链沿**恒等式**走，不沿相关性走 |
| **2** | 切分点必须同时满足：**①有方法 ②能观测 ③有人负责**。三条全中才切一个玛丽 |
| **3** | **红线要有玛丽去守**，不能只写一条约束（没人管它，它一定会破） |
| **4** | **共用的瓶颈必须单独切出来**（否则两个玛丽各自优化，一起把队列挤爆） |

**判据 2 用一个例子说明**：`单圈周期` 只满足②（能观测），不满足①（限速是物理的）和③（没人负责）→ **它只做拆解里的系数，不成玛丽**。

> ### 由此得出一条区分：**指标 ≠ 玛丽**
> **指标**是坐标/词汇（所有断言共用）；**玛丽**是"谁负责这个坐标"的组件。

### 🔶 18. 核心发现（脱产时间会计）

```
当班圈数 = (480 − 82) ÷ 35.5 = 11.2 圈        ← 与实测吻合

那 82 分钟花在：
   去程 15 + 回程 15 + 排队 30 + 作业 22
   └──── 60 分钟（73%）本可以省 ────┘  └ 27% 必须付 ┘
```

**排队 30 min 比作业 22 min 还长**——车在桩前干等的时间，比充电本身还久。

### 🔶 19. 红线要看**下尾**，而且红线之间会耦合

```
最低电量：均值 31.4%（看着很安全）／P1 16.2%／最小 11.4%（破线）
```

**均值完全掩盖了破线。** 而且那次破线发生在"排队 47 分钟"时——**"排队→等待→耗电→破线"是物理链条，因果安全**。

→ **该设约束的不只是"最低电量"，还有"充电排队时长"。**

### 🔶 20. 防患型动作要用"不良事件率"衡量，不能用"涨幅"

充电**不提升圈数**，它**避免更坏的情况**。用"圈数涨了多少"衡量充电，会得出"**充电有害**"（充一次就少跑半个班）。

### 🔶 21. 效果有**结构性**的，不只是数值性的

```
脱产时间 = 次数 × (往返 + 排队 + 作业)
```

**"减少次数""合并作业"不是"某个指标 ±δ"，是"改事件的拓扑"。** 而这类效果恰恰是最大的几根杠杆。

## 六、存储的具体形状（最近一轮，待你确认）

### 🔶 22. 图上两类节点，靠**一套共用词汇**连起来

```
【知识侧】可改，旧版留着
    词汇（两边共用）
   (车:7号) (桩:3号) (路线:1号线) (指标:电量) (指标:当班圈数) (动作:开始充电)

   (类别:电量20~25%) ──由规则──→ (信念:"什么叫充得偏早" v1)
   (信念:"25~30%比20~25%好" v3) ──谈到──→ (指标:当班圈数)
                               ──适用──→ (路线:1号线)
                               ──取代──→ (…v2) ──取代──→ (…v1)

【经验侧】只加
   (作业#4711) ──主体──→ (车:7号)
               ──在────→ (桩:3号)
        ▲  ▲  ▲  （三个事件 ──属于──→ 作业#4711）
        │  │  └─ (事件 08:15) ──执行──→ (动作:派往桩3)
        │  └──── (事件 08:55) ──执行──→ (动作:开始充电)
        └─────── (事件 09:20) ──执行──→ (动作:结束充电)

   (事件 08:12) ──主体──→ (车:7号)
                ──观测到{数值:22, 单位:%}──→ (指标:电量)
```

### 🔶 23. 四个要点

| # | 要点 |
|---|---|
| **1** | **两边不直接相连**，靠**共用词汇节点**（车、桩、路线、指标、动作）连。于是"这个指标上发生过什么"是一次遍历 |
| **2** | **数值挂在"观测到"这条边上**（值相同≠同一 → 不做节点）。**两个时间（发生时刻、记账时刻）挂在事件上** |
| **3** | **"作业"节点把事件拢成"一次"**——排队 40 分钟就是在作业内部算出来的 |
| **4** | **版本用取代边串起来**（v3→v2→v1），"当前是哪一版"= 没有箭头指向它的那个，不另存字段 |

### 🔶 24. 归类在图里 = **一个筛选，不是一条边**

```
「所有电量 20~25% 的充电」=
   找 (作业) → 它含"开始充电"事件 → 那时电量 ∈ [20,25) → 归入 (类别:电量20~25%)
```

**没有新边、没有新节点。** 规则一改，归类自动重算。

## 七、被推翻的（记下来，免得重犯）

| ❌ | 为什么推翻 |

| **"实验型实践 / 观察型实践"二分** | 你说：知识与实践相互依存，缺哪一半都是不完全状态 |

| **RQI / 薄接口 / 存储可替换**（更早） | 原文只是说"代码里别到处写 SQL"，被我放大成架构契约 |
