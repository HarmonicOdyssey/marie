# MARIE 存储设计 · v0.2

> **一套存储、两个层、三条通道、一条红线。**

参考 `HarmonicOdyssey/HeadOverHills` 的 `develop` 分支为 marie 设计存储层。
**这一版是重写，不是修补**——v0.1 建在一个已被推翻的前提上（把 marie 文档里一句"玛丽不直连存储"当成了架构契约）。v0.1 全套完整保留在 `archive-v0.1/`，未删除。

---

## 一句话

> **知识是普遍的、可修订的、由人确认才能改的；经验是具体的、只追加的、唯一不可重建的。**
> **两者结构完全相同，差别只在写入纪律。**
> **它们的结合方式是按起点条件分组、按 offset 对齐——因为同一方法的不同实践，链长和内容天差地别，平均会把它抹掉。**

## 贯穿全套的一个例子

免得抽象。所有文档都用它：

| | 内容 |
|---|---|
| 指标 | **里程碑按期率** |
| 目标 | ≥ 0.95，容差 ±0.01 |
| 方法 | **「提醒负责人」**，执行体：**人** |
| 知识里的预期 | +3 天 → 涨 0.20（容差 ±0.05）；+14 天 → 涨 0.15（容差 ±0.08） |
| 经验里的实践 | 2026-03-05 发起，+3 天观测到 0.88（基线 0.70，即涨了 0.18）|
| 37 次实践后的结论 | 起点 0.70~0.85 → 中位 +0.18；0.85~0.95 → +0.06；≥0.95 → +0.01 → **建议把适用条件收窄到 <0.85** |

## 相比 v0.1 的实质变化

| 变化 | 一句话 |
|---|---|
| **取消 RQI** | "存储可替换"是误读。存储只有一套，系统与它绑定是必然。"通用可复用可替换"说的是玛丽 |
| **新增「实践」实体** | v0.1 只记事件流水、再求均值——**把形状不同的链压成了一个标量**。均值在这里不是粗略，是错 |
| **溯源从表改为边** | v0.1 的"只记得最后一个来源"这个限制**只在表结构里存在** |
| **置信度由经验算** | v0.1 在知识里放"情态"字段——等于让知识自证可信 |
| **删掉抽取作业/字符偏移/表层形式** | 冗余，或**根本取不到** |
| **缺口不再永久留存** | 重跑就是验证；有些缺口永远补不上，必须能关掉 |
| **归一化改为作用域边界** | 真正的风险不是"相似度不够"，是**把 `DB-01` 和 `DB-02` 并成一个** |
| **经验与知识同构** | 同一套概念类型与关系；纪律靠"单一入口 + 独立审计"，不靠数据库 |
| **引擎：Neo4j** | 一个库同时装原文、图谱、经验、向量——**"存储只有一套"才成为事实** |
| **术语：账本 → 经验** | 而且"账本"不只是记账，是"发生了什么"的如实记录 |
