# 02 · 经验层

> 经验层存**具体的**东西：当时**究竟**发生了什么。
> 它和[知识层](01-知识层.md)**结构完全相同**，只有写入纪律不同：**只追加。**

---

## 一、一条红线：只追加

| 允许 | 不允许 |
|---|---|
| 新增一条记录 | 修改任何已有记录 |
| 追加一条"更正"记录 | 删除任何记录 |

**为什么**：经验是**唯一不可重建**的东西。原文丢了可以重导，知识错了可以重编，**经验丢了就永远丢了**。

三条配套纪律：

| 纪律 | 说明 |
|---|---|
| **误差不落库** | 只存事实：观测值、以及**生成预测时冻结的预期**。误差是现算的投影 → 所以知识改了，历史误差还能照原样重算 |
| **引用不抄内容** | 只记"当时依据的是 `提醒负责人@v3`"，**绝不把知识内容抄进经验** |
| **归因后置** | 记录时不替任何动作圈定结果。见第五节 |

---

## 二、「实践」是一等实体（本设计最要紧的一处补充）

**上一版设计的最大缺陷**：只记了一条平铺的事件流水，然后用"按方法求均值"把它压成一个数。
**那等于把形状完全不同的 N 条链压扁成一个标量**——链长、起点条件、执行过程、中途中断，全丢了。

**所以要把「实践」显式建出来。**

### 一次实践是什么

> **一次实践 = 一次方法，从发起到比对完成的全过程。**

```
一次实践
  起点      当时的状态：相关指标的值 + 世界
  依据      当时冻结的知识：方法 key@版本、拆解逻辑 key@版本、玛丽 key@版本
  动作      选了什么方法、执行体是谁、派发给了谁
  过程      观测序列（按「距起点多久」排列）
  终点      结束状态 + 终止原因
  形状      长度（几天 / 几步）
```

### 终止原因只有四种

| 终止原因 | 含义 |
|---|---|
| **比对完成** | 观测回流，预期与观测对上了账 |
| **前提未成立** | 方法压根没被执行 → **结果不可观测，这次预测无从验证** |
| **超期未观测** | 观察期过了还没观测，被心跳巡视发现 |
| **放弃** | 目标或环境变了，这次实践不再有意义 |

> **"前提未成立"为什么必须单独记**：没有它，**"方法不灵"和"压根没执行"在记录里无法区分**——复盘时会把执行问题误诊为知识问题，然后去改本来正确的知识。这是代价最大的一类误诊。

### 一次实践的完整样子（沿用全套的例子）

```
实践 #4711
  起点      2026-03-05，里程碑按期率 = 0.70，团队 5 人
  依据      提醒负责人@v3、拆解-里程碑按期率@v2、M-里程碑按期率@v1
  动作      选择了「提醒负责人」，执行体 = 人，派发给：张工

  过程      +0天  观测 0.70（基线）
            +3天  观测 0.88      ← 相对起点 +0.18
            +7天  观测 0.86      ← 相对起点 +0.16
            +14天 观测 0.82      ← 相对起点 +0.12

  终点      比对完成（+14 天那次观测回流后）
  形状      长 14 天，4 个观测点
```

**注意"相对起点"这四个字**——它就是[下一节](03-两层如何结合.md)要讲的 offset。

## 三、事件：经验里的最小记录单位

一个实践由若干**事件**组成。事件的类型是固定的枚举（**永不因新场景增加类型之外的列**，场景细节全部挂在负载里）：

| 事件类型 | 记什么 | 负载里的关键字段 |
|---|---|---|
| `goal` | 目标下达 | 指标、目标值、容差带、期限 |
| `decompose` | 拆解 | 输出指标、各输入指标及其子目标 |
| `select` | 方法选择 | 候选集、各候选当时的经验、实际选择、排序规则、知识版本 |
| `prediction` | 生成预测 | 方法与其版本、**冻结的预期**、观察期 |
| `execution` | 执行 | 预测 id、状态、执行体 |
| `observation` | 观测 | 指标、值、数据源、**是给哪条预测的** |
| `env_event` | 环境事件 | 不是系统动作引发的（公休、竞对动作、政策变化） |
| `report` | 报告 | 报告类型、关联的事件 |
| `knowledge_change` | 知识变更 | 条目 key、旧版本、新版本 |
| `heartbeat_overdue` | 心跳：预测到期未观测 | 预测 id |
| `heartbeat_silent` | 心跳：数据源静默 | 数据源、静默多久 |

### 三个字段要紧

| 字段 | 说明 |
|---|---|
| **业务时间** | 这件事发生在世界的哪个时刻 |
| **入账时间** | 这条记录什么时候写进来的 |
| **单调序号** | **顺序的唯一依据**。同一时刻可以有多条事件，顺序完全由它决定 |

**业务时间与入账时间是两个独立的轴**，合并它们就无法回答"**当时不知道，还是后来才知道**"（补录、倒序到达都会出现）。所以：

- 顺序**只由单调序号决定**，时间戳只承担"世界的时刻"
- 时间格式定宽（`2026-03-05T09:00:00Z`），否则字典序不等于时间序——**那种错不报错、只算错**

### 环境事件与自身动作记在同一条时间线上

原因很实际：一次动作之后，同期还发生了天气、竞对、别的动作。**如果在观测那一刻就回答"这个动作带来多少效果"，答案一定被污染，而且污染会被封进一个数字里，事后再也拆不开。**

记完整时间线则让干扰从"看不见的污染"变成"时间线上看得见的事件"，分析者可以排除它。**要诚实地说它没解决什么**：混淆不会消失，只是从"数据被污染"变成"分析有难度"——而后者可以持续进步。

## 四、经验与知识同构：同一个结构，两套纪律

| | 知识层 | 经验层 |
|---|---|---|
| 节点类型 | `g/s/t/l/f/r` | **同样的** |
| 关系类型 | 1/2/3/11/12/13/14 + 21 | **同样的** |
| 节点形状 | 同样的属性 | **同样的** |
| 同一件事再发生 | **合并**，计数加一 | **新增一条**，旧的绝不动 |
| 能否修改 | 能 | **不能** |
| 能否删除 | 能 | **不能** |

### 于是"一条知识实践了 100 遍"就是一句图上的话

```
(g) 提醒负责人                 ← 知识：方法（类）
     ▲
     │ 1 实例
     │
(s) 提醒负责人@v3              ← 知识：方法的具体版本
     │
     │ 11 参与                    ← **知识与经验的接缝**
     ▼
(s) 实践#4711     (s) 实践#4712   (s) 实践#4713  …… 共 100 个
     │                  │               │
     │ 13 导致          │ 13 导致       │ 14 先于
     ▼                  ▼               ▼
(f) 「+3天涨0.18」  (f) 「+3天涨0.04」  (f) 「…」
```

**"这条知识的经验" = 从(`提醒负责人@v3`)出发，沿 `11 参与` 边找回 100 个实践节点。**

每个实践节点再沿 `13 导致` / `12 发生` 展开，就是它那条链——**长度各不相同，靠 offset 对齐来对照**。

### 溯源就是一条边

```
(f) 「提醒负责人 影响 里程碑按期率」 --来源--> (:切片) 「…制度手册 V2.0 第 3 章…」
```

**不需要任何"提及表"**：一个概念出自哪些原文 = 沿边可达的切片集合。

> 上一版设计在这里错过一次：我把溯源做成了一张表。**而那个"一个节点只记得最后一个来源"的限制，只在表结构里存在**——在图里，概念指向多个事实、事实各自指向自己的来源，问题根本不存在。

## 五、不做归因

**这一节是上一版设计的又一处修正。**

上一版曾在执行事件里加一个字段，记"实际做的是不是知识说的那样"（当时的名字叫"执行偏离"）。**删掉了**，理由：

> 一个方法如果经常被偏离执行，和这个方法效果不好**也没区别**——至于**为什么**不好，**不应该由 marie 判断**。

"是执行问题还是知识问题"**本身就是归因**，而 marie 明说不做归因、只做簿记。所以：

| 记 | 不记 |
|---|---|
| 观测到多少（事实） | 为什么是这个数（归因） |
| 执行到了哪一步（事实：已派发/已确认/已完成/前提未成立） | 执行有没有走样、走样多少（判断） |

**留下的那四态不是归因，是操作事实**——派发了就是派发了。分析者事后可以从完整经验里做归因，那是**分析层**的事，不是 marie 的事。

## 六、经验的规模：四个会先撑爆的地方

| 东西 | 为什么长得快 | 怎么办 |
|---|---|---|
| **原文切片** | 只追加，且文档变更 = 新版本，**同一份文档改 10 次就留 10 份全文** | 旧版本归档到只读区；文本可压缩 |
| **实践的过程事件** | 每个节拍、每个活跃玛丽都可能产生观测 | 按时间分区 |
| **观测序列** | 与上图同阶 | 同上 |
| **报告** | 全部执行结果都进报告层 | 备查级别的只入账、只进列表，不推送 |

**唯一不可回收的是"实践"与"事件"本身**——它们是审计的依据。

## 七、本篇的代价

| 代价 | 说明 |
|---|---|
| **存储只增不减** | 这是买"可审计"付的钱。容量规划必须把它当**永久资产**，不能当缓存 |
| **查询变重** | 误差、账目、置信度全是现算。优势是**知识改了历史能重算**；代价是查询慢 |
| **没有数据库层的只追加保证** | 选了 Neo4j 就没有 SQL 那种"触发器直接拒绝 UPDATE"。纪律降为两层：**单一写入入口 + 独立审计**（见 [05](05-读写与纪律.md)） |
