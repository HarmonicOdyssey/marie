# 04 · 数据模型

> 一个库、一套节点类型、一套关系。原文、知识、经验、向量**全在里面**。

---

## 一、为什么是 Neo4j

| 需求 | 为什么它合适 |
|---|---|
| **一套存储** | Neo4j 5.x 同时提供**全文索引**与**向量索引** → 原文、图谱、经验、向量不必再拼第二套 |
| **溯源要是边** | 原图原生支持"事实 → 原文切片"这种边；不需要中间表 |
| **要问的问题本身就是图问题** | "这条知识的 100 次实践"、"A 导致 B 导致 C 跨文档"、"这个实体的所有叫法" |
| **平行边** | 同两个节点在不同世界里的同一种关系是**两条边**，原生支持 |

**代价（如实记）**：

1. `07 §四` 的「单进程 + 零新增依赖」被打破——多一个本地服务进程。
2. **没有任何数据库层的"只追加"保证**（Neo4j 没有 SQL 那种触发器）→ 纪律降为**单一写入入口 + 独立审计**（见 [05](05-读写与纪律.md)）。
3. **没有自增主键** → 单调序号要自己维护（见第五节）。

---

## 二、节点：三个维度叠加在一起

一个节点上叠**三类标签 + 一组属性**：

```cypher
// 一个知识层的普遍概念
(:Knowledge:GeneralTerm:World_Base {uid: "…", name: "服务器", …})

// 一次经验层的实践
(:Experience:SingularTerm:World_Base {uid: "…", name: "实践#4711", seq: 4711, …})
```

| 维度 | 取值 | 说明 |
|---|---|---|
| **层** | `:Knowledge` / `:Experience` | **纪律的分界线**。经验层只允许新增 |
| **概念类型** | `:GeneralTerm` / `:SingularTerm` / `:Time` / `:Location` / `:Fact` / `:RichContent` | **六种，两层共用，不增不减** |
| **世界** | `:World_Base` / `:World_某部门` / … | 可叠加多个 |

**另有一类节点不属于概念：**

| 标签 | 是什么 | 为什么不在六种里 |
|---|---|---|
| `:Slice` | **原文切片** | 它是**依据**，不是概念。原文层与知识层的关系是"引用"，不是"同一种东西" |

### 属性

| 属性 | 谁有 | 说明 |
|---|---|---|
| `uid` | 全部 | 节点的稳定标识（**必须确定性可派生**，见下） |
| `name` | `g/s/t/l` | 名称 |
| `description` | `f/r` | 描述 |
| `mood` | `f` | **语气**：`declarative` 陈述 / `imperative` 祈使 / `conditional` 假设 |
| `polarity` | `f` | **极性**：事实内容的真假（`true` 肯定 / `false` 否定） |
| `seq` | 经验层全部 | **单调序号**，顺序的唯一依据 |
| `business_time` | 经验层全部 | 业务时间，定宽 ISO 8601 UTC |
| `recorded_at` | 经验层全部 | 入账时间 |
| `world` | 经验层全部 | 所属世界（单值） |
| `knowledge_ref` | 经验层的预测/选择/变更 | `方法key@版本`，**只记引用，不抄内容** |
| `resource_type` / `storage_path` | `r` | 非文本资源的种类与原文件位置 |

**`polarity` 有一处极易搞错**：它描述的是**事实内容的真假**，不是**言语行为的有无**。
> "陈否认隐瞒" → `polarity = false`（事实内容是"陈没有隐瞒"），**不是** `true`（"陈确实说了否认"只是言语行为层面）。

### `uid` 必须确定性可派生

```
概念的 uid      = f(层, 类型, 规范化名称或描述)
关系的 uid      = f(源 uid, 关系类型, 目标 uid, 世界)
经验节点的 uid  = f(层, 类型, 实践 id, 事件内的角色)   // 或直接用 seq
```

**为什么不能用随机 UUID**：撤销一次实践后，同一件事再发生时，如果拿到的是新的随机 uid，那么**所有指向旧 uid 的引用（回退凭证、审计链）就永远对不上了**。确定性派生让"重建出来的还是同一个东西"成立。

## 三、关系：一种类型 + 一个编号

**所有关系都用同一种类型 `:LINK`，带 `rel_type` 属性**：

```cypher
(a)-[:LINK {rel_type: 11, world: "Base"}]->(b)     // 参与
(a)-[:LINK {rel_type: 13, world: "Base"}]->(b)     // 导致
```

**为什么不用 Cypher 的关系类型名**（`-[:CAUSES]->`）：

1. **关系编号表是唯一权威**——不必在 Cypher 类型名里再写一遍（两处写同一件事，迟早不一致）；
2. **"沿任意关系遍历一跳"是一句**：`MATCH (a)-[r:LINK]->(b)`，不必枚举七个类型名；
3. 与"预置关系 ID"这个概念一致。

**代价**：Cypher 语句的可读性下降（`rel_type: 13` 不如 `:CAUSES` 直观）。**用注释弥补**。

### 关系编号表（唯一权威）

| ID | 名称 | 源 → 目标 | 语义 |
|---|---|---|---|
| 1 | 实例 | `SingularTerm` → `GeneralTerm` | 单独概念是普遍概念的实例 |
| 2 | 是 | 概念 → 概念 | 两者指同一个东西 |
| 3 | 属于 | 概念 → 概念 | A 是 B 的一部分或一员 |
| 11 | 参与 | 概念 → `Fact` | A 参与了事实 B |
| 12 | 发生 | `Fact` → `Time`/`Location` | 事实发生在某时某地 |
| 13 | 导致 | `Fact` → `Fact` | **纯因果** |
| 14 | 先于 | `Fact` → `Fact` | **纯时序**（不含因果） |
| **21** | **来源** | `Fact` → `Slice` | **溯源：这个事实出自哪段原文** |

**`13` 与 `14` 绝不合并**：marie 的纪律是**不做因果推断**。如果 `13` 把"因果"和"时间先后"混在一起，图谱里每一条"先于"都会被读成因果断言——**等于系统在用知识层偷偷做因果推断**。

**新增关系从 44 起编号**（1–3、11–14、21 已用；22–43 留空）。

### 关系也可以带属性

```cypher
// 平行边：同两节点、同类型，不同世界 → 两条边
(a)-[:LINK {rel_type: 11, world: "Base"}]->(b)
(a)-[:LINK {rel_type: 11, world: "某部门"}]->(b)
```

## 四、世界与计数

**世界是一个维度，不是查询时加的过滤条件。** 放在查询端过滤，它一定会在某个连接处漏掉；放进结构里，漏掉在结构上不可能发生。

| | 怎么表达 |
|---|---|
| **经验层** | 节点带 `:World_X` 标签 + `world` 属性（单值，一条记录属于一个世界） |
| **知识层** | 节点可带**多个** `:World_X` 标签；计数分槽用**边**表达： |

```cypher
// 概念「服务器」在 Base 出现过 10 次、在某部门出现过 5 次
(n:Knowledge:GeneralTerm {name: "服务器"})
(n)-[:IN_WORLD {count: 10}]->(:World {name: "Base"})
(n)-[:IN_WORLD {count: 5}]->(:World {name: "某部门"})
```

**为什么计数放在边上**：Neo4j 没有 JSON 属性，"按世界分槽的计数"如果做成属性名（`cnt_Base`、`cnt_某部门`）就是动态属性名——**那是把结构藏进了字符串**。放在边上，它就是一个可查询的结构事实。

**并且它与"引用计数"是同一个机制**：计数归零 → 删边；一条节点没有任何世界边 → 删节点。

## 五、单调序号：Neo4j 没有自增主键

经验层需要"**顺序的唯一依据**"，而 Neo4j 不提供自增。做法：

```cypher
// 与写入在同一个事务里
MERGE (c:Counter {name: "experience_seq"})
SET c.value = c.value + 1
RETURN c.value AS seq
```

**三条约束**：

1. **必须在同一事务内**——Neo4j 的事务是 ACID，所以序号不会重复、不会跳（单进程写入的前提下）。
2. **只由单一写入入口分配**，别处不许自造序号。
3. **审计要检查单调性**（见 [05](05-读写与纪律.md)）——这是唯一能独立发现"序号被弄乱"的手段。

**为什么不用时间戳代替**：同一时刻可以有多条事件，**时间戳不构成全序**；而且时间戳可能被回填（补录）。顺序必须由一个**不可争辩的单调量**承担。

## 六、索引与约束

```cypher
// ① 知识层的查重键：同层、同类型、同名 → 只能是同一个节点（合并计数靠它）
CREATE CONSTRAINT kn_merge_key IF NOT EXISTS
FOR (n:Knowledge) REQUIRE (n.type, n.name) IS UNIQUE;

// ② 原文切片的稳定标识：世界 + 文档 + 单元号
CREATE CONSTRAINT slice_key IF NOT EXISTS
FOR (s:Slice) REQUIRE (s.world, s.doc_id, s.unit_id) IS UNIQUE;

// ③ 原文全文索引（溯源、检索）
CREATE FULLTEXT INDEX slice_text IF NOT EXISTS
FOR (s:Slice) ON EACH [s.text];

// ④ 概念向量索引（别名召回：把多种叫法认成同一个概念）
CREATE VECTOR INDEX concept_embedding IF NOT EXISTS
FOR (n:Knowledge) ON (n.embedding)
OPTIONS { indexConfig: { `vector.dimensions`: 1024, `vector.similarity_function`: 'cosine' } };

// ⑤ 序号索引（审计与按序扫描）
CREATE INDEX exp_seq IF NOT EXISTS FOR (n:Experience) ON (n.seq);
```

**经验层没有唯一约束**——这是刻意的：**同一件事发生两次就是两条记录**，任何唯一约束都会把它们合并掉。

## 七、写入纪律：退化为两层

Neo4j 没有 SQL 那种"触发器直接拒绝 UPDATE"，所以纪律不再由数据库兜底：

| 层 | 保什么 | 可迁移性 |
|---|---|---|
| **① 单一写入入口** | 经验层只有一条写路径；**只有新增，没有修改与删除的调用** | 引擎无关 |
| **② 独立审计** | 定期扫描"有没有被改过 / 序号有没有乱" | 引擎无关 |

**第 ② 层用上 `D23`（基岩不可玛丽化）那条原则**：用来报告"经验是否被篡改"的机制，**不能依赖经验本身**——审计要能独立跑，且它的记录不落在被审计的库里。

详见 [05](05-读写与纪律.md)。

## 八、三个需要你确认或需要实测的点

| # | 点 | 我的倾向 |
|---|---|---|
| 1 | **关系用单一 `:LINK` + `rel_type`，还是用 Cypher 类型名（`:CAUSES`）** | 单一 `:LINK`（权威只有一处）。代价是可读性，用注释补 |
| 2 | **世界计数放边上（`IN_WORLD {count}`），还是放动态属性名（`cnt_Base`）** | 放边上（图原生，且与引用计数同一机制） |
| 3 | **向量索引的维度（1024）与模型** | 待定——取决于你选哪个 embedding 模型。**维度写错会静默失效**（算出一个荒谬的相似度而不报错），所以这条必须实测确认后再写进约束 |
