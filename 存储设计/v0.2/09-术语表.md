# 09 · 术语表

> 本套术语的原则：**用自解释的词，不用过几天就忘的词。**
> 上一版有个字段叫"执行偏离"——那种名字注定会被误读，已被删除。

---

## 一、两个层

| 术语 | 定义 | 例子 |
|---|---|---|
| **知识层** | 存**普遍**判断：世界通常是什么样的。可修订 | "提醒负责人在按期率 0.7~0.85 时，+3 天预期涨 0.20" |
| **经验层** | 存**具体**经历：当时究竟发生了什么。**只追加** | "2026-03-05 对按期率执行了提醒负责人@v3，+3 天观测到 0.88" |
| **知识条目** | 知识层里可执行的依据（拆解逻辑 / 方法定义 / 玛丽定义），**带版本** | `提醒负责人@v3` |
| **原文切片** | 规范化后的一段原文文本，是溯源的落点 | 制度手册 V2.0 第 3 章第 2 段 |

## 二、经验层的单位

| 术语 | 定义 | 注意 |
|---|---|---|
| **实践** | **一次方法，从发起到比对完成的全过程**。一条完整的链 | 这是整套设计的核心实体。**不是"一次事件"** |
| **事件** | 经验里的最小记录单位（观测、执行、预测……） | 一个实践由若干事件组成 |
| **观测** | 对一个指标的一次测量 | 观测要指明"是给哪条预测的" |
| **预测** | 选了一个方法之后，**冻结**下来的预期 | 冻结是关键：之后知识改了，这次对账仍按当时那一版 |
| **终止原因** | 一次实践怎么结束的：比对完成 / 前提未成立 / 超期未观测 / 放弃 | 四选一 |
| **单调序号** | 经验记录**顺序的唯一依据** | **不是时间戳**——同一时刻可以有多条；时间戳还可能被回填 |
| **业务时间** | 这件事发生在世界的哪个时刻 | 与"入账时间"是两个独立的轴 |
| **入账时间** | 这条记录什么时候被写进来的 | 有了它才能回答"当时不知道，还是后来才知道" |

## 三、对照与聚合

| 术语 | 定义 |
|---|---|
| **offset** | **距起点的偏移量**（"第几天"，不是"哪一天"）。预期与观测都换算成它，长度不同的实践才能逐点对照 |
| **起点条件** | 一次实践开始时指标所在的区间（如"按期率 0.70~0.85"）。**聚合按它分组** |
| **分组聚合** | 按起点条件分组后分别统计。**不做全体均值**——均值会把"起点越高越无效"这个最重要的结论抹掉 |
| **到达时间** | 方法从发起到出现明显增益，用了多久 |
| **出带率** | 实际结果落在预期容差带之外的比例 |
| **前提未成立率** | 方法压根没被执行的比例。**没有它，分不清"方法不灵"和"压根没执行"** |

## 四、知识侧

| 术语 | 定义 |
|---|---|
| **指标** | 玛丽的锚点。有规范名、别名、可观测性、检查周期、方向 |
| **可观测性** | 可直接观测 / 可再分解 / 都不能。**"都不能"就是数据缺口的判据** |
| **拆解逻辑** | 指标怎么摊到它的输入指标上 |
| **方法定义** | 能影响某个指标的可执行动作，带适用条件、多维预期轨迹、执行体 |
| **玛丽定义** | 一个玛丽负责哪个指标、依赖什么、有哪些方法 |
| **适用条件** | 选这个方法之前先过滤掉的断言（"按期率 < 0.85"） |
| **预期轨迹** | **多维**、**按 offset 展开**的效果预期。远期自带更宽容差 |
| **执行体** | 人 / 机器 / 外部接口。决定"执行"这个动作实际长什么样 |
| **编译态 / 解释态** | 能写成确定性规则 / 保留自然语言当场判断。**解释态必须降低对账精度** |
| **置信度** | **由经验现算的投影**——样本量、分组覆盖、命中率、失败率。**知识不能自证可信** |

## 五、组装与运行

| 术语 | 定义 |
|---|---|
| **组装** | 从目标倒着展开成组件图，直到每个末端可直接观测 |
| **复用优先** | 先问池子里有没有，再判可观测，最后才报缺口。**顺序不可颠倒** |
| **缺口** | 走不下去的地方。**必须带位置**（"在这个指标的这一步做不了"） |
| **心跳巡视** | 独立定时器，问"什么都没发生，但本该发生吗" |
| **报告分层** | 入账（全部）/ 报告（全部执行结果，分立即·尽快·备查）/ 上报（只有缺口·预测失准·异常） |

## 六、易混淆对照（**最容易出错的地方**）

| A | B | 差别 |
|---|---|---|
| **知识** | **经验** | 普遍 vs 具体。结构相同，**纪律不同**（可修订 vs 只追加） |
| **实践** | **事件** | 一条完整的链 vs 链上的一个点 |
| **offset** | **业务时间** | "第几天" vs "哪一天"。前者可比，后者不可比 |
| **语气（`mood`）** | **极性（`polarity`）** | 这句话是什么语气（陈述/祈使/假设） vs 事实内容是真的还是假的 |
| **置信度** | **容差带** | 这条知识值多少信任（由经验算） vs 这次预期允许偏多少（知识里写的） |
| **前提未成立** | **方法无效** | 没执行 vs 执行了没用。**混了就会去改本来正确的知识** |
| **缺口** | **空结果** | "答不了，缺什么在这儿" vs "没有"。**只有前者带地址** |

### 已废除的词（不要再用）

| 废弃 | 改用 | 为什么 |
|---|---|---|
| **账本** | **经验** | "账本"太不通用了；而且它不只是记账，是"发生了什么"的如实记录 |
| **执行偏离** | （整个概念删除） | 那是归因，marie 不做归因 |
| **情态 / 声明·推演·实测** | **置信度**（由经验算） | 知识不能自证可信 |
| **提及表（`mentions`）** | **来源关系**（事实 → 切片） | 溯源是边，不是表 |
| **表层形式 + 出现次数** | （删除） | 拿不到的信息不要设计 |
| **抽取作业 / `extraction_run`** | （删除） | 冗余 |
| **缺口反查（`filled_by`）** | 重跑目标 | 重跑就是验证 |
| **RQI / 四类动作 / 薄接口契约 / 存储可替换** | **读知识 / 读经验 / 写经验** | 原设计把一句"别到处写 SQL"放大成了架构契约 |
| **`occurrence_count`（经验层）** | （删掉该列；知识层保留） | 经验层不许合并，计数恒为 1，没有意义 |
