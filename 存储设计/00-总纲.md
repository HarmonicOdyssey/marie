# 00 · 总纲

> **定位**：这是 marie 的存储设计。它只回答一件事——**知识与经验怎么存、怎么互相作用**。
> **一句话**：**一套存储、两个层、三条通道、一条红线。**

---

## 一、为什么存储是 marie 的核心问题

marie 的记忆被用在两件**要求完全相反**的事上：

| 用法 | 问题 | 对记忆的要求 |
|---|---|---|
| **支持判断** | "提醒负责人在什么条件下管用？" | 要**概括**：具体哪一天、哪个人，都不重要，重要的是规律 |
| **接受审计** | "3 月 5 日为什么决定去提醒他？" | 要**精确**：当时依据的是哪一版知识，一个字都不能错 |

一件事要求把细节磨掉只留规律，另一件事要求细节一个字都不能丢。**这就是整套设计的起点。**

所以存储不是"一个数据库"，而是**两个层**：一层存提炼出来的普遍规律，一层存具体发生过的每一件事。

---

## 二、两个层

| | **知识层** | **经验层** |
|---|---|---|
| 存什么 | **普遍的**：指标怎么拆、有哪些方法、方法在什么条件下预期什么效果 | **具体的**：某天某人对某个指标做了什么、结果观测到多少 |
| 一句话 | 世界**通常**是什么样的 | 当时**究竟**发生了什么 |
| 例子 | "提醒负责人：里程碑按期率在 0.8~0.95 之间时，+3 天预期涨 0.20" | "2026-03-05，对里程碑按期率执行了提醒负责人@v3，+3 天观测到 0.88" |
| 里有没有具体数值 | **没有**。指标的值不进知识层 | **有**。数值、型号、编号都在这里 |
| 写入纪律 | **可修订**：同一件事再出现，不新建，计数加一 | **只追加**：再发生一次就新增一条，旧的绝不动 |

**两层用的结构完全相同**：同一套概念类型（`g/s/t/l/f/r`）、同一套关系（1/2/3/11/12/13/14 是概念关系，21 是溯源关系）、同样的节点+关系形状。
**差别只在写入纪律**——而纪律靠"单一写入入口 + 独立审计"保证，不靠数据库。

> 为什么必须分：如果拿"合并计数"的结构去存经验，3 月 5 日和 3 月 12 日那两次会**被合并成一个节点、计数变成 2**，审计要的"那一次"就永远找不回来了。

## 三、一套存储

**整个系统只有一个存储：一个 Neo4j 库。**

```
┌─────────────────────────── Neo4j ───────────────────────────┐
│                                                             │
│  原文        切片节点（规范化后的原文文本 + 全文索引）          │
│                                                             │
│  知识层      概念 / 事实 / 指标 / 拆解逻辑 / 方法定义          │
│              + 向量索引（用于别名召回、语义匹配）              │
│                                                             │
│  经验层      实践 / 事件 / 观测 / 执行                        │
│              （与知识层同一套类型与关系）                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**为什么选它**：Neo4j 5.x 同时提供**全文索引**与**向量索引**，所以原文、图谱、经验、向量**全在一个库里**——不需要再拼第二套存储。这也让"溯源"变成一条边（经验 → 原文切片），不需要任何中间表。

> 「存储只有一套」不是口号，是这套选型的直接结果。

## 四、三条通道

知识和经验之间只有三条通道，**缺一不可**：

| 通道 | 方向 | 干什么 | 谁做 |
|---|---|---|---|
| **① 提炼** | 文本 → 知识 | 把制度、手册、SOP 里的经验抽成结构化的知识 | 抽取流水线（**离线**，人确认后入库） |
| **② 反馈** | 知识 → 经验 | 用知识指导下一次实践；实践时**冻结**当时用的是哪一版知识 | 运行循环 |
| **③ 巩固** | 经验 → 知识 | 从一堆实践里看出规律，据此修订知识 | **现算的投影**（见下） |

**① 和 ③ 都改变知识，但都必须有人的确认**——这是 `D8` 铁律：**执行期间不修改知识源**。

**③ 巩固是投影，不是表**：任何时候想知道"这条知识站不站得住"，就现场从经验里算一遍。不落库的好处是——**知识被修正后，拿新知识重新看同一批经验，结论自动更新**，因为经验从来没动过。

```
巩固(提醒负责人@v3)
   = 从经验里找出所有"依据 v3 的实践"
   → 按起点条件分组 → 每组算分布 → 现算，不落库
```

---

## 五、一条红线

> **经验只追加：只能新增，不能修改，不能删除。**

原因很直接：经验是**唯一不可重建**的东西——它没有任何上游。原文丢了可以重导，知识错了可以重编，**经验丢了就永远丢了**。

配套的三条：

| 纪律 | 说明 |
|---|---|
| **误差不落库** | 只存事实（观测值 + 生成预测时冻结的预期）。误差永远是现算的投影 → 所以知识改了，历史能重算 |
| **知识只追加版本** | 修改知识 = 追加新版本，旧版本永久保留；引用永远是 `key@版本` |
| **引用不抄内容** | 经验里只记"当时依据的是 `提醒负责人@v3`"，绝不把知识内容抄进去 |

## 六、核心决议一览

每条一行，详细理由见对应文档。

| 决议 | 一句话 | 详见 |
|---|---|---|
| **知识和经验同构** | 同一套概念类型与关系；纪律靠单一入口+审计分离 | [02](02-经验层.md) [05](05-读写与纪律.md) |
| **「实践」是一等实体** | 一次方法从发起到比对完成，是一条完整的链 | [02](02-经验层.md) |
| **对照用 offset** | 预期与观测都换算成"距起点多久"，长度不同的链才能比 | [03](03-两层如何结合.md) |
| **聚合按起点条件分组** | 不做全体均值——均值在这里不是粗略，是错 | [03](03-两层如何结合.md) |
| **置信度是投影** | 知识的可信度由经验算出来，不由它自己声明 | [03](03-两层如何结合.md) |
| **指标的值不进图** | 既不是节点，也不是图的属性；只在经验的事务记录里 | [01](01-知识层.md) |
| **数值不是节点** | 所以不存在"要不要归一化数值"的问题 | [06](06-归一化.md) |
| **溯源是边** | 事实 → 原文切片，一条关系就够，不要中间表 | [04](04-数据模型.md) |
| **归一只作用于"概念"** | 标识符（型号/ID/编号）绝不归一 | [06](06-归一化.md) |
| **缺口不永久留存** | 补上之后重跑目标即可；补不上的可以关掉 | [07](07-组装与缺口.md) |
| **不做归因** | 只记"效果如何"，不判"是执行问题还是知识问题" | [02](02-经验层.md) |

## 八、贯穿全套的例子

后面每一篇都用同一个例子，免得抽象：

| | 内容 |
|---|---|
| 指标 | **里程碑按期率**（`milestone_on_time_rate`） |
| 目标 | ≥ 0.95，容差 ±0.01 |
| 方法 | **「提醒负责人」**，执行体：**人** |
| 它的预期（在知识里） | +3 天 → 涨 0.20（容差 ±0.05）；+14 天 → 涨 0.15（容差 ±0.08） |
| 一次实践（在经验里） | 2026-03-05 发起，+3 天观测到 0.88（当时基线 0.70，即涨了 0.18） |
