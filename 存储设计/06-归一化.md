# 06 · 归一化

> 归一化要解决的事：**把多种说法认成同一个东西**。
> 而它最大的设计问题不是"用什么相似度"，是**"哪些东西允许被归一"**。

---

## 一、归一化在做什么

制度手册里写"前置防撞包"，另一份文档写"测距雷达"，第三份写"前置雷达"——**它们可能是同一个东西**。

如果不认成同一个，那么：
- 概念节点会重复，**图谱被碎片化**
- "这条知识的经验"会散在好几个节点上，**统计失真**
- 检索时用户搜"测距雷达"找不到"前置防撞包"的记录

归一化就是**把这些说法合并成一个节点，并累加出现计数**。

---

## 二、两道闸（编辑距离已废除）

| 闸 | 做什么 | 判定 |
|---|---|---|
| **① 精确匹配** | 同层、同类型、**名称完全相同** | 直接合并。**这是主路径** |
| **② 语义相近** | 名称的向量相似度过阈值 | 合并为候选，**阈值按指标词汇表校准** |

**编辑距离已废除**（原先与语义"且"关系）。

**废除的理由**：当时留着它是为了抓纯拼写变体（`UserServcie` vs `UserService`）。但这是一个很窄的案例，却要付**"误并"的风险**——而合并是**破坏性的**：错并一次，两条知识永久粘在一起。

**一个如实记录的已知缺口**：短字符串与型号（`DB-01` / `DB-02`）的语义向量区分力弱。**本条由下一节的作用域边界来兜**——它们**根本不允许被归一**。

---

## 三、作用域边界（本篇最要紧的一节）

**归一化会主动制造错误**：它会努力把 `DB-01` 和 `DB-02` 认成同一个东西——因为它们的向量确实很像。**而那是灾难。**

所以真正要设计的是**边界**：

| 东西 | 例子 | 是不是节点 | 归不归 |
|---|---|---|---|
| **概念**（业务实体、类别） | 前置防撞包 / 测距雷达 / 服务器 / 促销活动 | 节点 | **归** ← 归一的价值在这里 |
| **标识符**（型号、版本、ID、编号） | `DB-01`、`V1.5`、`#4711`、工单号 | 节点 | **绝不归** |
| **数值 / 属性值** | `2米`、`85%`、`+0.18` | **不是节点**（是属性或文本） | **不适用** |
| **时间 / 位置** | 2026-03-05、北京 | 节点 | **不靠相似度**——抽取时直接写成规范形式 |

### 三条边界为什么成立

**① "数值不是节点"，于是问题自己消解了。**

只要数值不作为图上的节点，"要不要归一 `2米` 和 `2 米`"这个问题**根本不存在**。

> 连带一条纪律：**指标的值不进图**（既不是节点，也不是图的属性）。知识层没有"当前值"这个概念；数值活在经验层的事件记录里。

**② "标识符绝不归"是防灾难的那一道。**

`DB-01` 和 `DB-02` 是**两台不同的设备**。归错了，两台设备的历史混在一起——**而且不可逆**（合并之后无法区分哪些记录原本属于哪台）。

**怎么判定"这是标识符"**——两道，取**并集**（宁可漏归，不可错归）：

| 判据 | 说明 |
|---|---|
| **形态规则** | 含数字、或形如编码（`V1.5`、`#4711`、`DB-01`）→ 跳过归一 |
| **抽取阶段打标** | LLM 能判断"这是不是一个具体的型号/编号"→ 由它标一个"不可归一"标记 |

**③ "时间/地点不靠相似度"**，而由抽取阶段**直接写成规范形式**（`2026年元旦` → `2026-01-01`）。
> 让相似度去判断"今年元旦"和"2026-01-01"是不是同一个，是把一件确定的事交给一件概率的事。

---

## 四、归一的后果，与"计数合并"是同一件事

归一化一旦成立，直接触发[知识层](01-知识层.md)的合并计数：

```
文档 A 出现「前置防撞包」   →  概念节点 (n) 新建，计数 1
文档 B 出现「测距雷达」     →  归一到 (n)，计数 2
文档 C 出现「前置防撞包」   →  (n)，计数 3
```

**于是"高频概念"天然浮现**——不需要跑昂贵的图聚类。这是合并计数的核心价值。

**而它的代价是：合并不可逆。** 所以边界必须保守。

---

## 五、归一只作用于知识层

| | 归一 |
|---|---|
| **知识层** | **归**（这就是它存在的意义：概括） |
| **经验层** | **不归**——经验是"当时究竟发生了什么"，`DB-01` 就是 `DB-01` |

**为什么经验层不归**：经验里出现的型号/编号，本身就是**个体**。它们通过关系连到自己的历史（"DB-01 这台设备出过什么问题"），**而这个历史正是归一会破坏的东西**。

---

## 六、归一的顺序（不能颠倒）

```
① 抽取 → 得到候选概念
② 排除：标识符（形态规则 ∪ 模型标记）           ← 先排除，再归一
③ 排除：时间/地点 → 走"直接规范化"，不走相似度
④ 精确匹配 → 命中即合并
⑤ 语义相近 → 过阈值即合并
⑥ 合并 → 计数累加；世界分槽计数按世界分别加
```

**为什么必须先排除再归一**：如果先归一再去排除，被错并的节点**已经粘在一起了**，排除来不及。

---

## 七、待实测

| 事项 | 说明 |
|---|---|
| **语义阈值** | 具体取多少（0.85？0.90？）**必须用真实指标词汇表校准**，不能拍。而且它应当是**可配置**的 |
| **嵌入模型与维度** | 维度写错会**静默失效**（算出一个荒谬的相似度而不报错）——必须实测确认后再写进索引约束 |
| **形态规则的具体式样** | 需要一份可维护的规则清单，且**必须能扩充** |

---

## 八、一句总结

> **归一化不是"尽量合并"，而是"在明确划定的范围内合并"。**
> 范围之外的东西——标识符、数值、时间、地点——**宁可留着不合并**，因为它们错了不能反悔。
