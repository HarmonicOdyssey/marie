# 07 · 组装、运行与缺口

---

## 一、组装：把目标摊成一张组件图

**组装 = 从目标出发，倒着展开，直到每个末端都能直接观测。**

```
① 盘点与复用优先（顺序不可颠倒）
     池子里有没有能产出这个指标的玛丽？
       有  → 直接复用，再往下展开它的输入指标
       没有，但这个指标可以直接观测 → 它就是一个叶子
       两者都不成立 → **组件缺口，记录位置**
② 逆向拆解
     用拆解逻辑把指标摊到它的输入指标上，逐个递归
③ 产出两样
     · 本次运行需要的组件图
     · 缺口清单（带位置）
```

**"复用优先"的顺序不能颠倒**——先问池子，再判可观测，最后才报缺口。颠倒的后果是**把本来能复用组件的地方报成缺口**，而缺口会让人去做一件根本不需要做的事。

### 三种形态不引入新概念

| 形态 | 什么时候出现 | 怎么表达 |
|---|---|---|
| **树** | 单目标，无共享 | 组件图 |
| **森林** | 多目标，**共享**原子实体 | 同一个组件图上多个根 + 标出共享的组件 |
| **图** | 指标互相影响、有环 | 同一个组件图 + 环上的边标为**时间延迟** |

**判定标准是"共享"，不是"目标数量"。** 一个目标也是树；三个目标但互不相干，仍然是三棵树，不是森林。

### 有环怎么办：时间延迟

一个指标拆下去又绕回自己（A 影响 B，B 又影响 A）：

```
A ──→ B ──→ A
```

**不合并、不丢弃，而是标成「时间延迟」**：A 对 B 的影响读**上一时间步**的 A，B 对 A 的影响读**上一时间步**的 B。于是每一步之内无环，跨步之间才有环。

> 这一条有个真实的坑：**如果"节点已存在就复用"的判断排在环检测之前，环会被静默当成共享节点**——图会以"已展开"的样子交出去，而"读上一时间步"这条规则永远不生效。**不报错，只给出一张看起来正常的错图。**

## 二、同一指标有多个玛丽怎么办

**不是按字典序挑一个，而是看经验。**

| 来源 | 怎么用 |
|---|---|
| **使用方偏好** | 如果场景配置里指定了偏好，按偏好 |
| **经验** | 比较备选玛丽所依赖的方法的**置信度**（样本量、命中率、分组覆盖） |
| **报缺口** | 都不可比 → **上报为缺口，请人指定**——不猜 |

**注意"经验"这一条正是[两层结合](03-两层如何结合.md)的一个消费点**：玛丽的选择本身也要靠经验，而不是靠名字。

## 三、缺口：五类，都带位置

| 类型 | 什么时候报 | 例子 |
|---|---|---|
| **数据缺口** | 指标既不可观测、也无法再分解 | "路过人数"没有数据源 |
| **知识缺口** | 有指标，但没有拆解逻辑 | 没有"里程碑按期率怎么摊"的逻辑 |
| **方法缺口** | 有拆解逻辑，但没有任何可行方法 | 知道要影响"阻塞数"，但不知道怎么做 |
| **组件缺口** | 池子里没有能产出该指标的玛丽 | 该指标没人负责 |
| **结构缺口** | 拆解本身有问题（如环、权重之和不为 1） | 输入权重加起来是 0.8 |

### 两条纪律

**① 缺口写成"在这个指标的这一步做不了"，不是"这个目标做不了"。**

```
❌  无法完成目标「提升里程碑按期率」
✅  组装：指标=阻塞数，这一步缺方法
```

原因：前者无法行动，后者**直接指出该补什么**。

**② 缺口是上报，不是资产。**

> **这一条修正了上一版设计。** 上一版要求"缺口清单永久留存，被补齐后可反查"，那是过度设计：
> - 补上之后**重跑目标**即可——缺口自然不再出现。**重跑就是验证，不需要反查表。**
> - 有些缺口**永远补不上**（企业场景大量如此——不是所有问题都有解答）。**那它就该能被关掉，而不是永远挂着。**

所以：

| 缺口的寿命 | 说明 |
|---|---|
| **运行期** | 上报给人，人去做该做的事 |
| **可关闭** | 补上了（下次重跑不再出现）／**接受它**（已知无解，不再上报） |
| **保留的价值** | **统计信号**——"这个月知识缺口集中在哪些指标"是有用的 |

## 四、运行循环

每个节拍做这些事：

```
① 读知识   当前指标该拆、有哪些方法、预期是什么、各方法置信度多少
② 对账     当前值与目标比 → 在容差带内？还是超差？
③ 选方法   超差 → 按经验与适用条件选一个方法
④ 生成预测 冻结预期（多维、轨迹、容差），定观察期        ← 写经验
⑤ 执行     派发（执行体：人 / 机器 / 外部接口）           ← 写经验
⑥ 收观测   观测回流 → 与冻结的预期对账（按 offset 对齐）   ← 写经验
⑦ 记账     全部入账；按报告分层决定推不推
```

**四条纪律：**

| 纪律 | 说明 |
|---|---|
| **不因目标达成而停止** | 达成之后继续观测、继续记账。系统**不结项**——目标达成只是"当前不用纠偏" |
| **正常运转时不推送** | 进入容差带后，账目照常累积，但**不主动推送**。推的是"需要人做一件只有人能做的事"，不是数字 |
| **执行体不产生分叉** | 人 / 机器 / 外部接口走**同一条**通路，差别只在记录里。**内核不为"人"保留任何专属路径** |
| **归因后置** | 只记"效果如何"，不判"是执行问题还是知识问题"（见 [02](02-经验层.md) §五） |

### 执行事件的四态

| 状态 | 含义 |
|---|---|
| 已派发 | 交给了执行体（人：提议已发出；机器：指令已下） |
| 已确认 | 执行体确认接受 |
| 已完成 | 执行体报告完成 |
| **前提未成立** | 方法压根没被执行 → **结果不可观测，这次预测无从验证** |

### 心跳巡视：问"什么都没发生，但本该发生吗"

心跳是**独立于业务事件**的定时器，只问两件事：

| 查什么 | 发现后 |
|---|---|
| **预测到期未观测** | 记一次 `heartbeat_overdue`，把该实践终止原因标为"超期未观测"，**上报** |
| **数据源静默** | 记一次 `heartbeat_silent`，**上报** |

> **心跳没产出报告就不留痕。** 但"该发生的事没发生"是事实，**发现它的结论要入账**。
> 心跳的价值在于：**没有它，系统只能对"发生的事"作反应**——数据源断了三天，账面会显示"指标平稳"，而那不是平稳，是瞎了。

### 报告分层

| 层 | 收什么 | 推不推 |
|---|---|---|
| **入账** | 全部事实 | 不推（就是经验） |
| **报告** | 全部执行结果与误差，按级别分：立即 / 尽快 / **备查** | 立即、尽快推；**备查只入账、只进列表，不推送** |
| **上报** | **只含三类：缺口 / 预测失准 / 异常** | 推 |

**"备查"必须真的不推**——上一版把"推不推"做成独立参数，于是"备查"级别的执行结果照样被推，直接导致"正常运转时推送显著减少"这条判据**不可能成立**。**级别与推送必须绑定。**

## 五、一条命令能跑完全部验收

验收必须**一条命令跑完**，否则它不会被跑。

| 验收组 | 内容 |
|---|---|
| **A（闸门）** | 状态重建、审计链、重放一致性、断裂降级、误差不落库 |
| **B** | 经验不可改、重放只读、单一写入入口、写入校验 |
| **C** | 换知识版本重算历史误差、样本量随结果返回、两个投影互不干扰 |
| **D** | 空经验、无快照、同时刻多事件、未来时刻 |

**A 组不过，就不进下一步。**
